# 3. Reviewing a run

**What you have:** every run is a folder in one schema (`logic/record/schema.py`). Inspection runs live in `data/runs/<DDMM>-<name>/`, sweeps in `data/datasets/<DDMM>-<name>/`. A run holds `run.json` (datasheet, status, view methods), `config.json` (the `cell.yaml`, hand-eye artifact and constants in effect), `session.json` (camera), `events.jsonl` (operator events), `manifest.json`, `answer.json`. Each view is a `steps/NNN/` with the capture bytes, mask, `step.json`, `view_state.json` and the accumulated cloud in `fused/`. The planner session sits in `ai/<seq>/`: `trace.jsonl`, the menu per turn, the vision transcripts and their tool images. A closed run is never edited. Everything computed afterwards goes to `data/derived/<run>/`: replayed step clouds, fits and the Rerun workspace `rrd/<run>.rrd`.

**What you need to do:** find the run, check its integrity, read what the planner and the vision agents did, replay it in the operator UI, then open the geometry in Rerun.

```bash
python -m inspection.record ls                         # runs: id, kind, object, status, rig, steps, size, verdict
python -m inspection.record ls --data                  # sweeps; --all for both
python -m inspection.record card <id>                  # every catalog field of one run
python -m inspection.record validate <id>              # schema, cross-file refs, manifest; --deep re-hashes
python -m inspection.record story <id>                 # the AI trace as text, in order

# operator UI on the recorded trace
python -m inspection.ui.app trace --run_dir=vbti/inspection/data/runs/<id>

# geometry in Rerun: full workspace when the run has step clouds, two-pane otherwise
python -m inspection.record show <id>
python -m inspection.record.rr.view list               # built workspaces under data/derived/*/rrd
python -m inspection.record.rr.view show <id>

# runs without recorded step clouds: replay them, then build the workspace
python -m inspection.investigation.run_replay.step_replay <id>
python -m inspection.record.rr.workspace --run <id>
```

**Done when:**
- `record ls` lists the run with the status and verdict you expect
- `validate <id>` prints `ok=True`
- `story` reads survey, then every inspect with its answer, in the order the run took them
- `ui.app trace` shows the question, every planner step and the answer card with its cited views
- Rerun opens on the run with poses, frames, masks and the cloud growing step by step

## Review commands

| Command | What it does |
|---|---|
| `python -m inspection.record ls [--data \| --all] [--object] [--status] [--source] [--rig] [--root]` | One line per run from its `run.json`, filtered |
| `python -m inspection.record card <id> [--root]` | Every catalog field of one run |
| `python -m inspection.record validate [<id> \| --all] [--deep] [--root]` | Integrity report per run; exits 1 if any run has an error |
| `python -m inspection.record story <id> [--root]` | Planner and vision trace as readable text |
| `python -m inspection.record show <id> [--out <f.rrd>] [--noopen] [--root]` | Build and open the Rerun view; `--noopen` writes only |
| `python -m inspection.ui.app trace --run_dir=<dir>` | Republish a run's newest `ai/<seq>/trace.jsonl` into the operator UI; follows a run still being written |
| `python -m inspection.record.rr.workspace --run <id> \| --all [--out] [--overlay-on]` | Build `data/derived/<id>/rrd/<id>.rrd` from the run and its derived tree |
| `python -m inspection.record.rr.view list \| show <id>` | List built workspaces, open one in the native viewer |
| `python -m inspection.investigation.run_replay.step_replay <id> [--out] [--attempts]` | Replay the run's object cloud view by view and verify it against `fused/cloud.npy` |
| `python -m inspection.fit.apply run <id> [--method] [--overwrite] \| sweep <ids> \| methods` | Backfill each step's `decomposition.json` with a registered fitter |

Schema reference: `docs/blueprints/data-engine/generated/schema.md` (generated by `python -m inspection.record.docgen`).
