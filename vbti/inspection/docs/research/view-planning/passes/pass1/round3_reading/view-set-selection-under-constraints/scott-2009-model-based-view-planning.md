Note: the sibling document `scott-2003-view-planning-survey.md` in this same directory covers Scott, Roth & Rivest's ACM Computing Surveys paper — a **taxonomy/critique of other people's methods** with no new algorithm. This 2009/ERB-1125 paper is different: it is Scott's **own algorithm** (the "3M" — Modified Measurability Matrix — method), the direct output of the "View Planning as a Set Covering Problem" (NRC-44892, 2001) line of work the 2003 survey cites but doesn't detail, now with pseudocode, closed-form sensor/pose-error models, and two real experiments with numbers. Where content overlaps (set-cover/ILP reduction, self-terminating requirement, generate-and-select architecture), I flag it and point to the survey note rather than re-deriving it; this note focuses on what is *new* here: the working algorithm, the viewpoint-generation procedure, the incidence-angle cutoff numbers, the explicit viewpoint-filtering/fallback step, and the pose-error-compensation experiment with actual measurability numbers.

## Core method / idea

**Multi-stage model-based view planning, decoupling scene exploration from precision measurement** (§1, §2.1, p.2). Traditional view planning does explore-and-measure simultaneously (repeatedly: image → augment partial model → pick next-best-view), which the paper calls "inherently sub-optimal as early selections cannot be revoked" (§2.1, p.2). Scott's approach instead: (1) a fast, pre-programmed *exploration* phase builds an approximate **rough model**; (2) that rough model is used to plan a **fine model** view plan as a single global optimization (not sequential NBV), exploiting "the high degree of intrinsic redundancy" in the rough model to make **revocable** viewpoint-selection strategies possible. This paper details only phase 2 (fine-model planning), which the author explicitly states he believes is "the key to view plan automation for high precision modeling and inspection" (§2.1, p.2).

**The 3M (Modified Measurability Matrix) algorithm** (Table 1, p.5; pseudocode reproduced):
```
Acquire rough model by pre-programmed exploration
Decimate the rough mesh model
Segment the rough model by feature type (optional)
While (Unscanned rough model regions)
    Generate optimal candidate viewpoint set
    Compute measurability, form measurability matrix
    Solve the set covering problem, select viewpoints
```
Core data structure: a binary **measurability matrix** M = [m_ij], rows = discretized surface points (rough-model mesh vertices), columns = discretized candidate viewpoints (§2.3, p.3). m_ij = 1 iff surface point i, viewed from viewpoint j, passes three tests: (a) **frustum occupancy** (inside the sensor's FOV/DOF), (b) **visibility** (unoccluded ray to both the optical transmitter and the receiver — triangulation sensors need both), (c) **specification-compliance** (estimated measurement precision and sampling density at that point, from that viewpoint, meet the user's numeric spec). Because (c) is baked into the boolean, **"coverage" in this formulation already means "coverage at acceptable quality"** — there is no separate quality layer bolted on afterward (directly relevant to branch Q1's second half; see Transfers).

**Viewpoint generation — the "Optimal Scanning Zone"** (§5, pp.7–8; Fig.5): for each rough-model surface point, dilate it along its local surface normal by a stand-off distance `f_d · R_o` (R_o = optimum scanning range, usually = R_min; `f_d` an empirically-tuned constant slightly > 1, found to work well at **f_d = 1.02**) to get a candidate viewpoint whose boresight axis is the negative of the dilation vector — i.e., **the candidate viewpoint is, by construction, orthogonal to the local surface**. The set of all such dilated points forms a smooth "optimal scanning zone" S_o (well-behaved on convex/planar regions, self-intersecting on concavities). Two generation variants: **Optimal Scanning Zone algorithm** (1:1 mapping, one viewpoint per surface point, §5 p.8) and a **Decoupled algorithm** (two rough-model resolutions — a coarser one `RM_v` for viewpoint generation, decimated separately from the surface-sampling mesh `RM_s`, giving further sub-sampling of V independent of S; §5 p.8, Fig.6). The decoupled variant is reported to outperform the "variable" (single-mesh) variant for natural objects with randomly-oriented shadow features (§7, "3M Algorithm Evaluation", p.13).

**Selection = minimum set cover, formalized as an ILP** (§3, "Theoretical Framework", pp.5–6; Eq.6–9): rows of M must each be covered by ≥1 selected column (Eq.7); an optional registration/overlap constraint (Eq.8) requires an image-based registration path between any two selected viewpoints, computed from viewpoint correlation; objective minimizes total view-plan cost (Eq.6, unit cost per view in the reported experiments — the "unicost SCP"). **Explicitly no feasibility constraint is included in the IP**: *"There is no need to include a viewpoint feasibility constraint in the above formulation. It is more efficient to avoid generating infeasible viewpoints"* (§3, p.6) — feasibility is handled upstream, at candidate-generation time (see Reachability below), not as an ILP constraint. The paper states plainly that the VPP "is isomorphic to the set covering problem (SCP), a well-studied problem in combinatorial optimization known to be NP-complete" (§3, p.6), and that for most reconstruction tasks a **fast greedy search** algorithm (Chvátal-style; cites Fisher & Wolsey 1982 on the greedy heuristic for covering/packing, ref [14]) gives view-plan lengths "close to the optimal" — with the caveat that "tasks demanding high view plan efficiency... can employ one of the more efficient but computationally expensive set covering algorithms" (§3, p.6) when it matters more than speed.

## Concrete results and numbers

- **Sensor/incidence-angle cutoffs (Eq.1, §2.5 p.4)**: measurement precision estimate σ̂_z = C_z·z² / {cos θ_yz · [1−U(|θ_yz|−t_yz)] · [1−U(|θ_xz|−t_xz)]}, where U is the unit step. In the triangulation (baseline) plane, precision degrades with an inverse-cosine relationship up to a cutoff angle **t_yz = 60°** (typical value); in the orthogonal scanning plane there is negligible inclination effect up to a cutoff **t_xz = 70°**, beyond which received energy drops below threshold and the point is simply unmeasurable. These are the paper's own stated "typical thresholds" — a directly citable numeric answer to branch Q7 (max admissible deviation from orthogonality), though the asymmetric 60°/70° split is specific to a triangulation sensor's baseline-vs-scan-plane geometry and does not map 1:1 onto a stereo/structured-light depth camera like a D405 (see Non-transfers).
- **Sampling density model** (Eq.2–5, §2.5 p.4): closed-form chord-based sampling-density estimate as a function of FOV, image resolution (N_x, N_y), scan length L_y, slant range, and both inclination angles — the mechanism by which "spec-compliance" (test (c) above) is evaluated per candidate m_ij, not a per-primitive view-count formula.
- **Rough-model sampling rules of thumb** (§4, p.7): experiments (cited to the author's own related work, ref [28]) found a rough-model sampling level **32× lower** than the target fine model gives good measurability prediction "for deep cavities" (worst case); for less complex/smoothly-flowing shapes it can be further reduced; the **lower bound** on rough-model sampling density is a rule of thumb **A_o/25**, where A_o is the frustum cross-sectional area. Partial, not full, answer to branch Q6 — this bounds *model* sampling density, not *view count per primitive*; view count still falls out of the set-cover solve, not a closed form.
- **Pose-error effects and compensation, Tsimshian stone mask** (§7, p.11, Table 3–4): with pose error injected (σ_p = 3%R_min = 4.26 mm, σ_a = σ_t = 3°) and **no compensation**, verified measurability drops to m̄_v = 0.9523 (n_Best=5 plan) / 0.9664 (n_gs=7 greedy plan) — down from the pose-error-free values (0.9663 / 0.9807 respectively, quoted in the surrounding text, §7 p.11). With **35% pose-error compensation** (a conservative-parameter-substitution scheme, §6.2 p.9–10), measurability recovers to 0.9642 / 0.9795 — "almost the same level of measurement performance in the absence of pose error" (§7, p.11).
- **Pose-error effects and compensation, Stanford bunny** (§7, p.12, Table 5): baseline (no sampling/pose error) probing-method plan n_Best=16 gives m_v=1.0, e_v=1.0; greedy plan n_gs=18 gives m_v=1.0, e_v=0.889 (i.e., greedy is **12.5% longer** than the best-known plan for identical full coverage — a concrete redundancy number, relevant to branch Q13/Q15). With sampling noise 0.3%R_min added (no pose error yet): decoupled algorithm gives n_gs=20 (m_v=1.0, e_v=0.8) vs n_Best=16 (m_v=0.9993, e_v=1.0). With sampling noise **and** pose error (σ_p=6.15mm, σ_a=σ_t=3°) at fixed n=16: compensation raises m̄_v from 0.9978→0.9992 and *cuts* the standard deviation from 0.0029→0.0011 (Table 5) — compensation's main measured effect is **variance reduction**, not just mean recovery.
- **View-plan efficiency, mask example** (§7 p.11): shortest plan found by the "probing" method (ref [25], not detailed in this paper) n_Best=5 gives m_v=0.9663, e_v=1.0 (efficiency 1.0 by definition since it's the best found); greedy search n_gs=7 gives m_v=0.9807, e_v=0.714 — i.e. **greedy used 40% more views** than the best-known plan on this instance. Together with the bunny's 12.5%/25% overshoot numbers above, this is concrete, citable evidence of the specific redundancy magnitude greedy search leaves on the table at small-to-moderate instance sizes (s=244 mask-segment vertices; s up to ~700 for the bunny rough model, decimated to |RM_v|=72 for viewpoint generation) — directly useful for branch Q13's "screen every candidate method for the redundancy failure" question, as a quantified baseline for how bad *even a mainstream, still-fast* selection heuristic can be.
- **Runtime** (§7, "Computational Efficiency", p.13): computing the measurability matrix (the dominant cost) took **3.6 minutes** for the mask's rear segment and **28.1 minutes** for the full bunny object, on a 2.6 GHz Pentium 4 (2005-era hardware); complexity is O(s²v) unsegmented, O(s²v/c²) with c-way segmentation (§3, "Computational Complexity", p.6–7), dominated by ray-tracing visibility tests (two per m_ij — source and receiver). Both target objects are far larger (hundreds of surface/viewpoint samples) than our stated instance size (tens of candidates, tens of regions) — reinforces that on 2020s hardware, at our scale, this is a trivially fast computation regardless of whether one uses greedy or exact ILP (branch Q3).
- **Result framing, repeated twice**: mask (§7 p.11) and bunny (§7 p.12) plans are both explicitly said to be "comparable to what a skilled operator could achieve" — the paper's own analytical-method quality bar, worth noting as an informal analytical-vs-human baseline (adjacent to, not a direct answer to, branch Q15's learned-vs-analytical question, since this paper predates learned NBV entirely).

## Load-bearing assumptions

1. **Positioning system is treated as a generic, low-DOF device (turntable/translation stage/coordinate-measuring-machine class), never a redundant serial arm.** §2.6's pose-error model (position error σ_p as an isotropic 3D Gaussian magnitude; axis error σ_a as a Gaussian half-angle cone; twist error σ_t as a Gaussian) is a **statistical residual-error model after calibration**, not a kinematic/IK model. There is no notion of joint configuration, IK solution multiplicity, or joint-space collision — "pose constraints due to mobility limitations are applied on a case-by-case basis" (§5, "Viewpoint Filtering", p.9) is the full extent of kinematic-feasibility treatment. This is the single biggest scope gap for our UR5e+RG2+D405 setting (branch Q10–Q12; see Non-transfers).
2. **Objects are characterized by Lambertian scattering and reasonable geometry/reflectance** (Abstract; explicitly re-stated as a limitation in §8, Conclusion, p.16: "characterized by Lambertian scattering... dropouts and outliers resulting from limited sensor dynamic range remain an open issue"). No handling of specular/glossy surfaces or the kind of per-view depth dropout our framing doc's fused-cloud setting explicitly has.
3. **The "rough model" is a real, high-fidelity laser scan, decimated (and optionally synthetically noised) — not a defective real-world reconstruction with genuine physical defects.** The two test objects (Tsimshian stone mask, Stanford bunny) are acquired at high resolution first, then artificially degraded for the experiment (§7, p.11–12: "sampling noise... was added," "surface sampling noise was not added... but pose error was introduced"). This is the closest this paper gets to "planning from an imperfect self-acquired model," but the imperfection is synthetic/controlled, not the real depth-dropout-plus-registration-offset character of our fused PLY.
4. **Full-coverage is the implicit universal goal** — the model specification "applies quantitative requirements for measurement precision and sampling density uniformly across the object with an implicit full coverage requirement," though the text immediately notes "In some applications, it may be appropriate to limit coverage to specified regions or to apply non-uniform measurement criteria" (§2.2, p.2) — an acknowledged but undeveloped extension point, never instantiated in the experiments (both test cases plan for 100% coverage of the whole object).
5. **The set-cover formulation implicitly assumes a full cover exists** — nowhere does the paper discuss what happens if some surface row has no admissible column (an empty row), i.e., a structurally uncoverable region. Same gap already flagged in the sibling 2003-survey note (branch Q11–Q12); this later, more concrete paper does not close it either.

## What transfers to our setting

- **Measurability-matrix quality-gating is the cleanest existing precedent for "coverage at a quality floor" (branch Q1).** m_ij is only 1 if the point meets the numeric precision/sampling-density spec from that view — coverage and quality-floor are the *same* boolean test, not two separate objectives to trade off. This is stronger and more concrete than the 2003 survey's treatment (which cites the same idea but without the worked equations) — Eq.1–5 here are the actual quality predicate one would binarize. Directly usable as a template: define our own per-region "in-spec from this view" boolean (e.g., orthogonality within tolerance + resolution/coverage-density floor), then the selection problem literally reduces to minimum set cover, matching Scott's own reduction almost exactly.
- **"Avoid generating infeasible viewpoints" is an explicit, citable architectural recommendation for up-front filtering over post-hoc IK filtering (branch Q10).** §3 states directly that omitting a feasibility constraint from the IP is *more efficient* than including one — i.e., feasibility should be resolved during candidate generation (a capability-map-like filter), not during selection. This is a stronger, more direct statement than the 2003 survey gives on this exact point.
- **§5 "Viewpoint Filtering" documents two of the branch's four fallback-ladder rungs explicitly, in the same short paragraph, applied together in one real system** (branch Q9, the headline deliverable): *"Viewpoints violating collision avoidance zones are deleted with the expectation that associated surface regions will be covered by adjacent viewpoints on S_o. Pose constraints due to mobility limitations are applied on a case-by-case basis, mapping the optimum viewpoint to the nearest feasible pose. Excessive mobility constraints will negate the advantages of the proposed viewpoint generation scheme."* (§5, p.9). That's: **(i) hard filter and discard**, relying on the redundancy of neighboring generate-per-point candidates to recover coverage of the same region from elsewhere, plus **(ii) slide the viewpoint to the nearest feasible pose within its admissible region** — applied "on a case-by-case basis" (i.e., not a single uniform policy, chosen per situation). The explicit warning that over-aggressive mobility filtering "will negate the advantages of the proposed viewpoint generation scheme" is a load-bearing caution directly applicable to our hard-minimum reachable-shell radius: **if too much of the ideal scanning zone gets discarded/slid away, the whole "one ideal view per feature" premise stops paying for itself.**
- **The Optimal Scanning Zone (surface-normal dilation by a tuned stand-off factor) is a clean, citable formalization of "the ideal view is orthogonal, offset by a fixed multiple of standoff distance," at the finest (per-vertex) granularity** (branch Q5). It generalizes naturally to the coarser "one view per face/one ring per cylinder" recipe: apply the same normal-dilation rule at the primitive level (face centroid + normal for planar faces, radial dilation at fixed height intervals for a cylinder) instead of per-vertex. Worth citing as the fine-grained ancestor in the citation chain the branch brief asks for (CMM accessibility cones → Scott's per-vertex optimal scanning zone → primitive-level face/cylinder rules → feature clustering/subdivision).
- **The generate-then-globally-select architecture is independently motivated here by revocability, not by VLM legibility** (branch Q4) — same point the 2003 survey makes about synthesis-vs-generate-and-test, but this paper adds the concrete mechanism (rough model → measurability matrix → ILP/greedy) showing *why* decoupling generation from selection buys something real: early NBV-style choices can't be revoked, global set-cover selection can consider the whole candidate set at once. Converges with our VLM-presentability argument from an unrelated direction.
- **Chvátal-style greedy is the field's practical stopping/minimality criterion, but comes with a quantified redundancy tax** (branch Q13): the greedy-vs-probing-method gaps above (40% on the mask segment, 12.5–25% on the bunny) are concrete numbers to cite when arguing that a small-discrete-set VLM budget cannot tolerate "just run greedy" without either (a) accepting that tax or (b) using something closer to exact (which, per the paper's own runtime numbers at *our* much smaller scale, is cheap).
- **Pose-error / registration-offset framing directly supports the framing doc's ~4 cm fused-cloud-vs-single-view motivation.** §6.1's finding that pose error primarily degrades *frustum occupancy* (the geometric "is this point even in view" test) more than visibility or spec-compliance, and that redundancy is the main mitigant, gives a mechanism-level explanation for why a several-mm-to-cm registration offset between a fused survey cloud and a live single view matters: it's not just noise on the measurement, it can silently exclude points from a candidate's frustum that the plan assumed were covered.

## What does NOT transfer, and why (negative findings — first class)

- **No IK, no joint-space treatment, no capability-map false-positive rate (branch Q10–Q12).** Confirmed by the pose-error model's own vocabulary (§2.6): position/axis/twist error are *statistical residuals after calibration*, not *reachability* in any robot-arm sense. "Mobility limitations" (§5, p.9) is a one-sentence, un-elaborated placeholder — no discussion of what a robot-arm-specific reachability filter would look like, no error-rate numbers for it, no discussion of IK solution multiplicity or Cartesian-pose-vs-joint-configuration framing for "what is a view." This is a clean, confirmed gap consistent with the sibling 2003-survey note's finding on the same question — a later, more concrete paper by the same author line still does not fill it, which is itself informative (the gap isn't an oversight specific to the 2003 survey; it's absent from this author's entire research program in this era).
- **No reachable-shell coverage-loss numbers or benchmark (branch Q11).** Nothing resembling ObjView-Bench's ~45/128-views or 0.13–0.17-coverage-loss figures exists here; positioning-system limitations are acknowledged in the abstract ("positioning system limitations") but never quantified experimentally in either test case (both objects are freely rotatable/graspable test targets on a lab positioner, not tabletop-fixed objects viewed by an arm with a hard minimum standoff).
- **No treatment of "reachability changes the shape of the answer," i.e. objective redefinition under structural uncoverability (branch Q12).** As noted under load-bearing assumptions, the set-cover formulation assumes a cover exists; no discussion of a best-available-view-per-region-plus-unreachable-region-report fallback appears anywhere, including in the "Open Issues and Future Research" list (§8, p.16), whose three named future directions are accuracy/robustness (reflectance, step edges), efficiency (faster rough-model acquisition, discretization tuning), and theory (optimal discretization, shape complexity in the overlap constraint) — structural uncoverability is not named as an open problem at all.
- **No learned selection, no learned budget predictor, nothing to compare against BENBV/GenNBV/SCVP (branch Q14, Q16).** This is a 2005-era analytical/statistical method; "learned" appears nowhere. Not informative on the learned-vs-analytical question except as a pure-analytical baseline (see the "comparable to a skilled operator" framing above).
- **No submodularity discussion (branch Q2).** The set-cover reduction (§3, Eq.6–9) is the same structural anchor the 2003 survey note already flags — classical unweighted set cover is submodular (textbook fact, not asserted in this paper), but the paper never raises or tests whether adding a continuous orthogonality/quality *weighting* on top of the binary measurability test would preserve that property. Notably, this paper's own m_ij is *already* boolean (quality folded into a 0/1 spec-compliance test, not a continuous weighted score) — so even this paper's own formulation sidesteps the question rather than answering it: **it stays inside the classical, provably-submodular regime specifically by refusing to make quality a continuous weight.** That is itself a design lesson worth carrying forward: if we want the clean submodular-greedy guarantee, keep the per-region contribution boolean (in-spec / not), not a continuous orthogonality score.
- **No max-k-coverage formulation (branch Q1, second half).** Same as the 2003 survey: every formal statement (Eq.6 minimizes Z; §3 states VPP "is isomorphic to" SCP) is minimum-set-cover-for-a-coverage-target, never maximum-coverage-for-a-fixed-budget. If Albert's requirement is "VLM gets k views, cover as much as possible," this paper (like its 2003 predecessor) gives no precedent for that dual framing.
- **No defect-driven region importance, no primitive decomposition.** The rough model is a uniform decimated mesh; there is no concept of "this region matters more because a defect is suspected there," and no superquadric/cuboid/primitive-level object representation anywhere — surface space S is always a flat point/vertex set. Consistent with, and reinforcing, the sibling survey note's findings on branch Q18–Q19 (both remain open gaps as far as this author's body of work goes).
- **Triangulation-sensor-specific numbers (60°/70° cutoffs, Eq.1's baseline-plane-vs-scan-plane asymmetry) do not map directly onto a D405.** The D405 is a stereo/active-IR-pattern depth camera without the same single-baseline-triangulation geometry (transmitter and receiver in one housing along a fixed optical baseline, per Fig.3) that Eq.1 is derived for. The *qualitative* lesson (precision degrades with incidence angle up to a cutoff beyond which data is unusable, and the cutoff is sensor-geometry-dependent and anisotropic) transfers; the specific 60°/70° numbers should not be quoted as our operating thresholds without re-deriving them for the D405's own noise model.
