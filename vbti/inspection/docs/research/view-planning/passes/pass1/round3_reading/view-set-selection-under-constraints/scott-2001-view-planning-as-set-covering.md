## Core method / idea

A short, dense **formulation paper** (no experiments) that does two things:

1. **States the view planning problem (VPP) as a 0/1 integer program (IP)**, built directly on top of a *measurability matrix* M = [m_ij] (binary, s surface elements × v candidate viewpoints) that the authors developed in an earlier companion paper (ref. [10], Scott/Roth/Rivest, ISR 2000). Row i of M is a surface element (rough-model vertex); column j is a candidate viewpoint; m_ij = 1 iff surface element i is measurable from viewpoint j. This binary encoding is stated to already exist (built from "geometric scene knowledge embedded in the rough model") — the *content* of what makes a view "measure" a point (incidence angle, range, occlusion, etc.) is **not** defined in this document; it is inherited from ref. [10].
2. **Adds a second, structurally different constraint — image-based registration** — on top of the coverage IP, and shows how to express it algebraically (§2.3–2.5) as a graph-connectivity requirement over the *selected* viewpoint set, using the same measurability matrix as its only input (via a cross-correlation between viewpoint columns). This second constraint is the paper's actual novel contribution over ref. [10]; the base set-covering IP (§2.1) is presented as "previously developed."

The paper explicitly frames itself as being about **problem formulation, not solution method** — §3's closing paragraph states the field's more important open problem is *"a sound theoretical basis for determining a suitable set of viewpoint variables and surface constraints... optimal sampling of viewpoint space and the exploratory object model,"* not the IP solve itself.

## Concrete results and numbers

This is a theory/formulation paper; the only "results" are a worked toy example and complexity bounds, not empirical measurements.

- **Core IP** (§2.1, Eq. 1–3, p.1 col.2):
  - Minimize Z = Σ_{j=1}^{v} x_j  (Eq. 1) — minimize the **count** of selected viewpoints.
  - subject to Σ_{j=1}^{v} m_ij x_j ≥ 1, ∀i ∈ S  (Eq. 2) — every surface element covered by ≥1 selected viewpoint.
  - x_j ∈ {0,1}  (Eq. 3).
  - This is stated to be "known as the *unicost set covering problem*" (§2.2 opening line, p.2).
  - **Infeasibility fallback, verbatim (§2.1, p.2 col.1)**: *"Occasionally, there may be no feasible solution, in which case we wish to have the minimal number of non-compliant constraints, that is — maximum surface covering."* This is the paper's only mention of anything resembling max-coverage: it is an **exception-path objective switch**, triggered only when full coverage is infeasible, not a parallel or default framing.
- **Non-unicost variant** (§2.2, Eq. 4, p.2): Minimize Z = Σ c_j x_j with per-viewpoint movement costs c_j — noted as "a somewhat more difficult programming problem," judged unnecessary for their imaging environment (uniform/insignificant movement costs assumed).
- **Reachability handled outside the IP** (§2.2, p.2 col.2, verbatim): *"A separate issue relates to physical limitations on the range of motion and degrees of freedom of the positioning system which effect viewpoint feasibility. There is no need to include such constraints in the above IP formulation. It is more efficient to avoid generating infeasible viewpoints at the viewpoint generation stage."* — an explicit, reasoned design decision to filter unreachable candidates **before** optimization, not encode reachability as an IP constraint.
- **Registration constraint** (§2.3, Eq. 5–10, p.2–3):
  - Cross-correlation of two viewpoints: σ_kj = (M_{S,k} · M_{S,j}) / m_S (Eq. 5), where m_S = max_k |M_{S,k}| over all candidates — i.e., dot product of the two viewpoints' coverage-column-vectors, normalized by the single most-covering candidate's coverage count.
  - Registration feasibility test: σ_kj ≥ t_r (Eq. 6), with **t_r "typically around 20%"** (p.2 col.2) — the only numeric threshold in the whole document.
  - Binary adjacency X_kj = 1 iff σ_kj ≥ t_r; symmetric registration-adjacency matrix A = [a_kj], a_kk = 0.
  - Cumulative reachability matrix C = A¹ + A² + ... + A^(v−1) (Eq. 7) counts paths of all lengths ≤ v−1 between viewpoint pairs.
  - Global requirement stated in prose (§2.3, p.3, verbatim, their emphasis): *"The viewpoint registration graph must be at least simply connected."*
  - Necessary-and-sufficient connectivity test restricted to the selected set N: c_kj ≥ 1 ∀k,j ∈ N, k≠j (Eq. 8–9).
  - Folded into the IP as a genuinely bilinear (non-linear) constraint over the decision variables themselves: c_kj ≥ x_k·x_j, ∀k,j ∈ V (Eq. 10, and restated as the "final" registration constraint, Eq. 14 in §3).
- **Worked 4-viewpoint example** (§2.4, Fig. 1, p.3): four candidate viewpoints with registration-adjacency edges only 1–3, 2–4, 3–4 (i.e., graph is the path 1–3–4–2, no direct 1–2 edge). Reduces (after removing redundant "don't-care" entries) to three global constraints (Eq. 11): x₁x₂x₃x₄ ≥ x₁x₂; x₁x₂x₄ ≥ x₁x₄; x₂x₃x₄ ≥ x₂x₃. Stated result, verbatim: *"Testing the registration graph in Figure 1 against the constraints at equation set 11, we observe that the example candidate NBV set fails the registration test."* I.e., the paper demonstrates concretely that a candidate view set chosen to satisfy coverage alone (e.g., just {v₁, v₂}, which have no registration edge between them) can fail a secondary structural requirement even though coverage itself is fine — the exact "bolt a non-coverage requirement onto the cover, and watch the pure-coverage answer break it" pattern the branch selected this paper for.
- **Two-stage repair strategy** (§2.5, p.4, verbatim): *"we note the constraints are non-linear, making the IP non-linear. However, we can solve for the set covering constraints alone and then enforce registration compliance as part of the fitness function. If required, a minimal number of views can be added to satisfy the registration constraint and render the solution feasible overall."* — solve pure coverage first, patch minimally afterward, rather than jointly optimizing coverage + registration in one non-linear IP solve.
- **Complexity figures** (§2.1 p.1–2, §2.5 p.4):
  - Measurability-matrix computation: O(v·s²).
  - Typical dense model reconstruction: s ≈ 10⁵ surface points; unreduced viewpoint-space discretization ≈ 10¹¹ levels.
  - Complexity reduction (§2.1, p.2 col.1, verbatim): *"segmenting the object surface into patches. In this case, separate measurability matrices are computed for each segmented patch and v and s refer to subsets associated with individual patches."*
  - Registration-matrix C: O(v³) if computed for the full candidate set once; reducible to O(c·n³) if delayed and restricted to only the c candidate *solutions* actually evaluated, where n = |N| ≪ v is the solution size.
- **§3 solver landscape** (p.4): exact methods (branch-and-bound, cutting-plane) "guaranteeing optimal results... can be computationally prohibitive even for modestly sized IPs." For "most medium-to-large IPs," the field falls back to greedy search, simulated annealing, genetic algorithms, Lagrangian relaxation, or neural-network heuristics [refs 1,2,5,7,9,13]. Their own characterization of VPP as an IP class: *"falls into the category of a medium-to-large IP with non-random data and moderate density [12]"* — i.e., they self-assess their own problem as generally requiring heuristics, not as trivially exact-solvable — but this assessment is for *scene-scale* v,s (≈10⁵–10¹¹ before reduction), not for a single per-patch sub-problem.

## Load-bearing assumptions

1. **The binary measurability matrix M already exists and already encodes whatever quality/admissibility criteria matter** (incidence angle, range, occlusion, sensor FOV) — this paper takes M as a given input from ref. [10] and never defines what makes m_ij = 1 vs 0. Any orthogonality tolerance, defect-size threshold, or other quality floor would, in this framework, have to be baked into the *construction* of M (as a hard admissibility cutoff), not into the objective (Eq. 1) or the primary constraint (Eq. 2) — those remain pure cardinality-minimization and pure coverage.
2. **Candidate viewpoints are pre-generated from a "rough model"** — a polygonal mesh from a separate, pre-programmed rapid exploration phase (object reconstruction case) or a CAD model (inspection case). Reachability/kinematic feasibility is assumed handled entirely upstream of the IP, at this generation stage (§2.2).
3. **Unicost is the default; non-unicost (per-view movement cost) is presented as strictly harder and unneeded for their setup.** No positioning-system cost structure is assumed beyond this binary choice.
4. **Registration is needed only because positioning-system precision is assumed inferior to sensor precision** (§2.3 opening sentence) — i.e., the registration constraint exists to compensate for *robot/stage pose error*, not for anything to do with view quality or orthogonality per se. It is a stand-in example of "a second hard requirement," not itself directly about orthogonality.
5. **The registration constraint's "point overlap" formulation is explicitly acknowledged as necessary but not sufficient** (§2.3, p.2 col.2: *"we need to add a geometric complexity requirement to the overlap region to fully constrain registration in all directions and rotations... This is being pursued"*) — the paper flags its own registration test as an approximation, not a finished model.
6. **No submodularity, no approximation-ratio, no greedy-guarantee discussion anywhere.** Greedy search is named only as one item in a list of five heuristic families (§3, citing Fisher & Wolsey [5] "On the greedy heuristic for covering and packing problems" — a paper that *is* about greedy approximation guarantees for covering problems, but Scott et al. never invoke or discuss its guarantee here).

## What transfers to our setting

- **The exact structural precedent the branch selected this paper for**: a secondary, non-coverage hard requirement (their registration-graph connectivity) layered on top of a minimum-set-cover core, expressed within the same IP, using the same underlying measurability matrix as its only data source (Eq. 5, cross-correlation is literally a dot product of two columns of M). This is a clean template for how an orthogonality or reachability requirement could be bolted onto our own coverage objective — either (a) as a *pairwise/relational* constraint over the selected set (their approach, needed because registration is inherently about *pairs* of views overlapping), or (b) baked directly into the *admissibility* of individual matrix entries (the alternative they don't use for registration but that Tarbox & Gottschlich [15] used for grazing-angle thresholds per the companion survey document already in this project's notes). **Orthogonality in our setting is a per-view scalar property, not a pairwise relation** — so route (b) (bake an orthogonality/incidence cutoff into what counts as "covering" a region, i.e., redefine m_ij to require both visibility and angular admissibility) is the structurally correct analogy, not route (a) (registration's graph-connectivity machinery). Reachability, being also per-view (not pairwise), maps the same way — and this paper says exactly that for reachability already (§2.2): filter it out of the candidate set before the IP even runs, don't constrain the IP with it.
- **Direct, reasoned precedent for our reachability fallback-ladder question**: this paper explicitly chooses fallback-ladder option (i), "hard filter and discard," and gives the *reason* — computational efficiency, not view-quality preservation (§2.2, p.2: "more efficient to avoid generating infeasible viewpoints at the viewpoint generation stage" than to encode feasibility as IP constraints). This is a genuine, checkable citation for option (i) being a documented field choice, but it is explicitly justified by IP tractability, not by any claim that discarding is quality-neutral — worth citing carefully, not as an endorsement that discarding is harmless for action-space integrity.
- **Direct precedent for our "coverage unattainable → redefine the objective" question**: the infeasibility fallback ("minimal number of non-compliant constraints, i.e., maximum surface covering") is the field's earliest explicit statement that when full coverage cannot be achieved, the objective itself must switch from minimum-cardinality-for-full-coverage to a max-coverage/least-shortfall framing — directly relevant to the branch's "best-available view per region + explicit unreachable-region report" question, though the paper doesn't develop this beyond one sentence.
- **Direct precedent for per-primitive/per-patch decomposition as a complexity-reduction device**: §2.1's "segmenting the object surface into patches, [computing] separate measurability matrices... for each segmented patch" is a real, citable precedent for solving view selection *per spatial patch* rather than globally — structurally adjacent to (but not identical to) our primitive-level decomposition. It is motivated purely by computational complexity (shrinking v, s), not by exploiting canonical-primitive geometric priors (box faces, cylinder rings) — see negative findings below for the gap this leaves.
- **Directly informs "can we just solve this exactly at our scale" (branch Q3)**: the paper's own complexity figures (s≈10⁵, v≈10¹¹ unreduced, at *whole-scene* scale) are what makes heuristics necessary in *their* setting — and by their own logic (patch segmentation shrinks v,s to per-patch subsets), a per-primitive sub-problem with "tens of candidate views, tens of surface regions" is exactly the shrunk-down regime their own complexity-reduction technique targets, several orders of magnitude below where they say exact IP solvers become prohibitive. This is a legitimate citation for "the field's own scaling argument implies our instance size should be exactly solvable," even though they never state that conclusion themselves.
- **A citable, worked minimal counterexample (§2.4, Fig. 1, Eq. 11) that a pure-coverage-optimal set can fail a secondary hard requirement** — directly reusable as an illustrative point when arguing that greedy/ILP coverage selection alone is insufficient once orthogonality or reachability enter as requirements, independent of whether submodularity holds.
- **The paper's own closing statement of what remains unsolved** (§3, final paragraph) — *"the field requires a sound theoretical basis for determining a suitable set of viewpoint variables and surface constraints — that is, optimal sampling of viewpoint space and the exploratory object model"* — is essentially a 2001 articulation of exactly what RQ2/RQ3 in our framing doc are asking (how do we derive/compose the view set from the object's geometry), stated by the authors as the field's *harder*, still-open problem relative to the solvable-once-formulated selection IP.

## What does NOT transfer, and why (negative findings — first class)

- **No submodularity or greedy-approximation-guarantee treatment at all (branch Q2).** Greedy search is listed as one of five interchangeable heuristics (§3) with no discussion of when/whether it has a provable ratio for this specific IP, no citation of Nemhauser/Wolsey-style submodular-greedy guarantees despite citing Fisher & Wolsey [5] (a paper that *is* on this exact topic) only as a generic heuristic reference. This paper cannot be used to argue submodularity is or isn't preserved once quality-weighting is added — that question is simply not asked here.
- **No numeric orthogonality/incidence-angle threshold, no closed-form per-primitive view count, no FOV/overlap/defect-size formula (branch Q6/Q7).** The only numeric threshold in the document is the registration cross-correlation cutoff, t_r ≈ 20% overlap — about image-registration overlap, not about surface-normal deviation or defect detectability. The measurability matrix's actual admissibility criteria are entirely deferred to ref. [10], not present here.
- **No experiments, no reported view counts for any real object or object class (branch Q13).** Despite a Semantic Scholar summary elsewhere suggesting "experimental results using a modified greedy search algorithm" exist under this DOI, the 4-page document actually fetched here contains no experimental section, no figures of real objects, and no reported (min, achieved) view-count pairs. Treat any such empirical claims as belonging to a different/longer version not retrieved, not to this document.
- **No primitive-shape-specific viewpoint generation (box face, cylinder ring) anywhere (branch Q5).** "Candidate viewpoints are generated from the geometric scene knowledge embedded in the rough model" (§2.1) is the full extent of what this paper says about candidate generation — it is entirely silent on *how*, deferring again to ref. [10]. The patch-segmentation complexity reduction (§2.1) is spatially/complexity motivated, not primitive-shape motivated — it does not name boxes, cylinders, or any canonical primitive, and does not claim patches correspond to geometric primitives. This is a real, citable gap supporting the branch's novelty claim (Q19): even the paper closest to "coverage + segmentation" in this reading list does not fuse primitive decomposition with view planning.
- **No IK, no capability map, no false-positive-rate analysis, no discussion of Cartesian-pose-vs-joint-configuration action definition (branch Q9/Q10/Q11).** "Positioning system" is treated as an abstract black box with a "range of motion and degrees of freedom" (§2.2) — no manipulator kinematics, no redundancy, no multiplicity of IK solutions is discussed anywhere. Nothing here bears on the UR5e/RG2/D405-specific reachability questions.
- **No learned/data-driven selection of any kind (branch Q15).** 2001, pure combinatorial-optimization framing; entirely pre-dates any learned NBV or VLM-adjacent literature.
- **No treatment of survey-cloud defects (pose error, depth dropout, fused-vs-single-view offset) propagating into the measurability matrix (branch Q17, partial).** The "rough model" terminology is analogous to our survey PLY (a preliminary, imperfect geometric input used to plan subsequent views), but this paper never discusses the rough model's own error/noise — that is explicitly the subject of a separate companion paper (Scott, Roth, Rivest, "Pose error effects on range sensing," Vision Interface 2002 — cited in the companion survey document already read for this project, not in this document's own reference list). This document cannot be used as evidence for how defect-laden geometry should be handled; only as terminology precedent for the two-stage "rough model → precision measurement" pipeline shape.
- **No discussion of a "view" as a Cartesian pose vs. a joint configuration, nor any manipulator-specific content** — "viewpoint" throughout is an abstract point/pose in an unspecified positioning-system space; this document offers no leverage on branch Q10.

## Assessment for the branch

This document earns its selection: it is the cleanest available worked example of "add a non-coverage hard requirement to a minimum-set-cover formulation, expressed in the same IP, keep the coverage objective exact-minimality," which is structurally exactly what our orthogonality and/or reachability requirements would need to become if bolted onto a coverage objective. Its single most actionable transfer is the **structural distinction it draws (without naming it as such) between per-view admissibility (route: bake into the measurability-matrix entries, as reachability already is by their own §2.2 design choice) and pairwise/relational requirements (route: graph-connectivity-style IP constraints, as registration needs)** — orthogonality, being per-view, belongs on the first route, so this paper argues (by structural analogy, not by saying so directly) that orthogonality should tighten what counts as "covering" a region rather than requiring registration-style machinery. Its complexity figures also make a legitimate, citable case that our instance size is trivially exact-solvable by the field's own scaling logic. It is a pure-theory, zero-experiment document, however: it supplies no numeric orthogonality threshold, no per-primitive recipe, no reachability mechanism, no submodularity analysis, and no empirical view-count data — all of those must come from other sources already flagged elsewhere in this branch's reading list (ref. [10] for measurability-matrix content, the 2002 pose-error paper for survey-cloud defects, Tarbox & Gottschlich [15] for the grazing-angle-threshold precedent already surfaced in the companion survey document).
