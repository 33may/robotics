# Raffo, Romanengo, Falcidieno, Biasotti — "Fitting and recognition of geometric primitives in segmented 3D point clouds using a localized voting procedure" (CAGD 2022)

- arXiv: 2205.15426 (v2), submitted 2022-05-30. Full text: https://arxiv.org/html/2205.15426v2
- Authors: Andrea Raffo, Chiara Romanengo, Bianca Falcidieno, Silvia Biasotti (CNR-IMATI, Genova)
- Selected for: Hough/voting alternative to RANSAC, explicit "RANSAC can be deceived by point cloud artifacts" motivation, and a per-segment fit-quality score (MFE) that looks like a candidate reliability signal.

## Core method

A three-stage pipeline per **already-segmented** point-cloud patch (Sec. 3.3, Fig. 7):

1. **Pre-processing (Sec. 3.2.1):** Robust local normal estimation. For each point p_j, take a neighborhood N_j within radius D, run a local Hough Transform to find the most-voted plane π̂_j through that neighborhood, and take its normal as n̂_j. This is itself a small Hough vote per point, not PCA — the paper's argument is that HT is more robust to noise/outliers at this stage than a covariance-based normal estimate. Points with high **Mean Fitting Error** (MFE, Eq. 1: mean point-to-plane distance over the neighborhood, normalized by the segment's bounding-box diagonal l_j) are discarded; the threshold is "2% of maximum among length, width, height of bounding box" (Sec. 3.2.1).
2. **Initial parameter estimation + standardization (Sec. 3.2.2, Figs. 3–6):** Using the cleaned normals, get an initial coarse estimate of center/axis/radius per primitive family (sphere: tangent-plane intersections give circles, Fig. 3; cylinder/cone: axis from normal field then project to 2D and fit a circle/line, Figs. 4–5; torus: separate upper/lower-circle and small-circle recognition, Fig. 6), then roto-translate the segment into a canonical/standard pose so the primitive's parameters are centered near the origin.
3. **Localized Hough voting (Sec. 3.3):** With the segment in standard position, the initial estimate "gives a hint to the HT technique of where the optimal solution is, thus eliminating the problem of the unboundedness of the parameter space" — i.e., the whole point of the pipeline is to turn an unbounded/high-dimensional HT parameter search into a small local search. This localization is what lets them extend HT past the classic plane/sphere case to **cylinder, cone, torus** with only 1–3 free parameters left to vote over (planes/circles: 3; tori: 2; spheres/cylinders/cones: 1) (Sec. 3.3.1). Complexity is O(M·S), M = accumulator cells, S = points in the segment.
4. **Type selection:** if the primitive type is unknown, all 5 families are fit and the one with lowest MFE is kept (this MFE-as-model-selection step is the "recognition" in the title).

Supported primitive vocabulary (Sec. 2, Fig. 1): **plane, sphere, cylinder, cone, torus** — parametric/infinite-surface representations (Hesse form; center+radius; axis+radius+location; vertex+axis+half-angle; center+major/minor radius+axis). No superquadrics, no cuboid decomposition, no bounded-extent output (see Negative findings).

**Segment aggregation (Sec. 4.1, Table 1):** once each segment is fit and typed, a second stage does complete-linkage hierarchical clustering over segments using primitive-specific relational distances (e.g., parallel/incident planes via normal cross-product and point-plane distance; equal-radius/parallel-axis/incident-axis cylinders; equal-aperture/parallel-axis/equal-vertex cones). Dendrogram cut thresholds: 1e-10 for planes, 1e-1 for the others (Sec. 4.2.1). This step is about merging over-segmented parts of the *same* primitive, or discovering CAD-style relations (parallelism, coincidence) between *different* primitives — not about bounding a single primitive's extent.

## Quantitative results

**Synthetic primitives, initial-estimate sanity check (Sec. 3.4, Fig. 8):** Fig. 8's caption is explicit that this figure evaluates only the **coarse initial estimates** from Sec. 3.2.2 ("Initial estimates for various segments, without noise (left) and with increasing noise (right)"), described in-text as "a sanity check" — it is *not* a test of the final localized-HT-fitted result. Each row is a *partial* segment ("different pieces of" — verbatim from the caption; text elsewhere calls these "a one-eighth portion of a full sphere," "a small portion of a cylinder," "a one-eighth portion of a cone," "a one-eighth portion of a torus"), and columns are four noise levels: noise-free, U(−0.1,0.1), U(−0.5,0.5), U(−1.0,1.0), added directly to point coordinates (not a sensor/range-error model), on shapes of radius/scale ~1–2 (so U(−1,1) is noise comparable in magnitude to the shape's own radius — a very high relative-noise regime, not comparable to our mm-level sensor noise on cm–dm objects). Reported per-primitive errors at each level (full table, our own compilation from the figure):
  - Sphere: radius error 0.00 / 0.02 / 0.05 / 0.03; center L2 error 0.01 / 0.02 / 0.02 / 0.06.
  - Cylinder: radius error 0.00 / 0.00 / 0.04 / 0.47; **axis vector L2 error ‖a−â‖₂ 0.00 / 0.00 / 0.00 / 0.44**.
  - Cone: half-angle error 0.00 / 0.00 / 0.01 / 0.03; **axis L2 error 0.00 / 0.00 / 0.19 / 0.37**; vertex L2 error 0.02 / 0.02 / 0.03 / 0.03.
  - Torus: r_min error 0.00/0.01/0.02/0.09; r_max error 0.02/0.02/0.04/1.18; center L2 0.02/0.03/0.04/0.07; **axis L2 0.00/0.01/0.02/0.07**.
  Converting the axis L2 errors to an angle via ‖a−â‖₂ = 2·sin(θ/2) for unit vectors: cylinder axis ≈ **25° at the highest noise level**, cone axis ≈ 11° at U(−0.5,0.5) and ≈ 21° at U(−1,1), torus axis ≈ 4° at the highest level. **We independently searched the full paper (Secs. 3.3–4.4) and confirmed no table anywhere reports axis/parameter accuracy for the *final*, post-voting fitted primitive** — only MFE and ACC/TPR/TNR/PPV/NPV (fit quality / recognition-correctness metrics, not parameter-precision metrics) are reported past the initial-estimate stage. So Fig. 8 is the *only* axis-direction-error data in the paper, it is for the coarse pre-HT estimate only, on synthetic coordinate noise at scale-comparable-to-radius magnitudes, on partial (~1/8) coverage. Separately, CPU times are reported for a differently-described experiment ("100 point clouds per primitive type, 400–1,600 points" — Sec. 3.4, paragraph after Fig. 8): cylinder 24.8 s, sphere 17.0 s, cone 28.9 s, torus 49.4 s (Intel i9 3.6 GHz, MATLAB, per-segment); **the paper does not state whether this timing set is the same data as Fig. 8 or a separate one**, and reports no parameter-error numbers for it. Method "can fail when applied to particularly small segments suffering from strong noise levels" (Sec. 3.4).

**ABC dataset, noise sweep (Sec. 4.2.1/4.2.2, Figs. 9–11):** ABC = "a collection of one million CAD models created for researching geometric deep learning" — synthetic, exact-CAD ground truth, not real scans. Example models: 22,803 pts/18 segments → MFE 0.0019; 13,455 pts/26 segments → MFE 0.0036; 15,726 pts/99 segments → MFE 0.0042. Gaussian-noise sweep on one model: σ=0.10 → MFE 0.0106; σ=0.25 → MFE 0.0212; σ=0.50 → MFE 0.0347, **and at σ=0.50 "two cylinders are mislabeled as cones and thus wrongly clustered."** This is the paper's one explicit noise-induced type-confusion failure, and it is cylinder↔cone, not plane confusion.

**Fit4CAD benchmark (Sec. 4.2.2, Table 2):** Fit4CAD is a purpose-built benchmark for evaluating primitive-fitting/recognition on CAD-derived point clouds "affected by some point cloud artifacts (e.g., undersampling or missing data)" — synthetic defects layered on CAD models, not real sensor scans. Reports TPR/TNR/PPV/NPV/ACC per primitive family, averaged: plane ACC 0.999 (TPR 0.980, TNR 1.000); cylinder ACC 0.998 (same-cylinder query), 0.991 (same-radius query); cone ACC 0.994 (same-cone), 0.952 (same-axis); sphere ACC 0.976 but TPR only 0.667; torus ACC 0.958, TPR only 0.583 — **spheres and tori are the weak cases, with recognition (TPR) degrading well before overall accuracy would suggest**, because the classes are rare/ambiguous relative to negatives.

**Comparison to method [21] (approximate-implicitization + hierarchical clustering) (Sec. 4.3, Table 3):** their method beats [21] on a specific model (ACC 1.000 vs 0.951) and on Fit4CAD overall (ACC 0.999 vs 0.950), but **at the highest noise level (σ=0.50) both methods collapse equally (TPR 0.076 vs 0.076)** — i.e., the claimed robustness advantage does not hold at high noise; both are near-random there.

**"Industrial scans" (Sec. 4.4.2, Figs. 13–14):** two real-world point clouds (282,534 pts / 39 segments, MFE 0.0091; 529,006 pts / 51 segments, MFE 0.0120), with segmentation taken from RANSAC results published by a prior paper (GlobFit-style, ref [5]). **No ground truth is available for these objects** (stated explicitly), no scanner/sensing-technology description, no defect characterization (single- vs multi-view, registration error, dropout) is given at all — the paper does not say whether these are single-scan or fused/registered multi-view clouds. One misclassification is reported: a cone segment labeled as a sphere. This is the paper's only real-scan validation, and it is qualitative (visual figures + MFE numbers), not benchmarked against ground truth.

**Learning-based segmentation input (Sec. 4.4.1, Fig. 12):** demonstrates the aggregation step can clean up over-segmentation from a learned segmenter; MFE values 0.0036–0.0102 across 5 examples. No further detail on what the learned segmenter or data source was, in the fetched text.

## Confidence / reliability signal

The one score the method exposes is **MFE** (Eq. 1: mean point-to-primitive distance over the segment, normalized by segment bounding-box diagonal) — used two ways: (a) as a *model-selection* criterion, picking the primitive family with lowest MFE when type is unknown, and (b) as a global admissibility gate: ε = 5% of the model's bounding-box diagonal; if all candidate primitive types exceed ε, **none is accepted as a satisfying fit** (Sec. 3.3). This is a residual-RMS-style score, not a posterior probability or calibrated confidence — the paper never validates MFE against a downstream-task failure threshold, and never reports an MFE distribution for correct vs. incorrect fits that would let you pick a working ε. It is exactly the "inlier ratio / residual RMS" family named in the branch questions, with no calibration exercise attached.

## Load-bearing assumptions

1. **Segmentation is a solved prerequisite, not part of this method.** Verbatim: "we assume that these segments are assigned in input or possibly extracted by existing software, e.g., by using the pre-segmentations provided by other methods, such as RANSAC... or some recent learning-based approaches" (Sec. 3.2, paraphrased from fetch). The paper's contribution is fitting+typing+relating *given* a segment, not carving the segment out of a raw scan.
2. **Noise model is synthetic and coordinate-additive** (uniform ±σ or Gaussian σ added directly to point positions), never a range-sensor model (no incidence-angle dependence, no depth-vs-lateral anisotropy, no dropout, no registration/multi-view fusion error). This is a real gap against our defect profile.
3. **All primitives are treated as complete/closed-form infinite surfaces during fitting** — partial coverage is handled implicitly (sphere fit from a patch of tangent planes still gives a full sphere equation; cylinder from an arc still gives a full infinite cylinder). Fig. 8 (Sec. 3.4) does demonstrate the *initial estimate* on ~1/8-coverage partial segments, but there is no systematic minimum-coverage/minimum-arc-angle sweep, no test of the *final* fitted result under partial coverage, and no asymmetric/one-sided dropout scenario ("half a cylinder, dropout on one side," matching our glossy-surface case) anywhere.
4. **Ground truth for real scans is absent** — the only real-world test (Sec. 4.4.2) has no ground truth, so accuracy claims there are purely qualitative/visual.

## What transfers to our setting

- The **localized-voting idea itself** (use a cheap initial estimate to collapse HT's parameter space, then vote only in the reduced local space) is a legitimate alternative to RANSAC for plane/cylinder/sphere/cone fitting, and directly targets our stated failure mode (RANSAC being deceived by point-cloud artifacts) — this is a real candidate technique to prototype for Branch 2 (plane+cylinder+sphere+cone vocabulary question).
- The **cylinder↔cone confusion at high noise** (ABC σ=0.50) is a concrete, citable data point that geometric-similarity confusions (not random misclassification) are the realistic failure mode as noise rises — useful for framing what "decomposition unreliable" looks like (RQ on failure detection).
- Fig. 8's initial-estimate axis-error trend — flat near-zero error up to noise ≈ 1/3 of object radius, then a sharp nonlinear blow-up (cylinder axis error jumping from ‖Δa‖≈0 to ‖Δa‖≈0.44, i.e. ~25°, between the U(−0.5,0.5) and U(−1,1) noise levels) — is a qualitative pattern (threshold-like breakdown, not graceful degradation) worth carrying into Branch 1's synthesis even though the absolute noise magnitudes don't map onto our mm-scale defects.
- MFE is a usable off-the-shelf residual-based fit-quality number, in the same family as inlier-ratio/residual-RMS scores named in the branch questions — but it needs the calibration work ourselves; the paper does none of that (directly answers "is there a calibrated score" question: no).
- Confirms (again) that RANSAC-family methods are the implicit baseline this whole sub-literature reacts against, reinforcing that Branch 2's contract (plane+cylinder+sphere+cone RANSAC) has known, named failure modes in the literature, not just our own observation.

## What does NOT transfer, and why (negative findings — first-class)

1. **Axis-direction error is reported, but only for the coarse pre-voting initial estimate, not the final fitted primitive, and only under synthetic coordinate noise at magnitudes comparable to the shape's own radius.** Correcting an earlier draft of this note: Fig. 8 (Sec. 3.4) *does* report ‖a−â‖₂ axis-vector errors for cylinder/cone/torus across 4 noise levels (see table above; ≈25° cylinder-axis error at the highest tested noise). But (a) this is explicitly the "initial estimate" sanity check, before the localized-HT refinement step that is the paper's actual contribution — we searched the rest of the paper and found no table anywhere reporting final post-voting axis/parameter accuracy; (b) the noise magnitudes tested (up to ±1.0 on a radius-1.5 shape, i.e. coordinate noise ~67% of object scale) are wildly larger, relative to object size, than our mm-level registration/depth-bias errors on a cm–dm object, so even this number doesn't transfer as a usable magnitude — only the *qualitative* trend (axis error stays ≈0 up to ~33%-of-radius noise, then blows up nonlinearly past that) is potentially informative. This paper still cannot directly answer Branch Q1/Q7's quantitative angular-error-vs-our-noise-level question; we need a different source (PCA/jets/VCM normal-estimation literature, or the paper's own final-fit accuracy which it doesn't report) for that number.
2. **No bounded/finite primitive extents are recovered.** Outputs are infinite plane/cylinder/sphere/cone/torus equations, confirmed by direct search of the method section — there is no boundary, extent, or centroid output. This directly fails Branch Q3 ("scan this face orthogonally needs a face centre and face size, not a plane equation"). The clustering/aggregation stage (Sec. 4.1) merges segments belonging to the same primitive but still only outputs relational distances between infinite primitives, not a bounded patch.
3. **No real sensor noise model.** Every noise experiment (synthetic Sec. 3.4, ABC Sec. 4.2.1, Fit4CAD Sec. 4.2.2) uses coordinate-space Gaussian/uniform noise added to exact CAD points. There is no incidence-angle-dependent range error, no registration/multi-view fusion error, no glossy/dark dropout model. This means none of the noise-robustness numbers (MFE vs σ, or the Fig. 8 axis errors above) can be mapped onto our depth-bias / registration-error / dropout defect profile without a large, unstated extrapolation. Directly negative for Branch Q11–Q13, Q19 (which ask whether this kind of paper's noise model matches our defect profile — it does not).
4. **Partial-coverage is tested, but only qualitatively, only for the initial estimate, and without a quantified minimum-coverage threshold.** Correcting an earlier draft of this note: Fig. 8's segments are explicitly partial ("a one-eighth portion of a full sphere," "a small portion of a cylinder," "a one-eighth portion of a cone," "a one-eighth portion of a torus" — Sec. 3.4 text), combined with the noise sweep above, and Sec. 3.2.2 states "the method is also able to deal with parts of primitives, as shown in Section 3.4." So the paper's claim of partial-coverage robustness is not vacuous — it is demonstrated on one qualitative example per primitive type at one coverage fraction (~1/8), for the initial estimate only. But there is still no systematic sweep over coverage fraction (e.g. what happens at 1/16, or at 1/2 with asymmetric/one-sided dropout like our glossy-side scenario), no quantified minimum arc-angle/surface-fraction threshold, and no test of the *final* fitted result's accuracy under partial coverage. Directly relevant but insufficient for Branch Q6 (partial cylinder + glossy dropout) — it's suggestive that ~1/8 coverage works for the initial estimate at low noise, not a threshold we can design against.
5. **No calibration of MFE (or any score) against downstream task failure.** The ε=5%-of-bbox-diagonal threshold is a hand-set global admissibility gate, not derived from an experiment relating fit quality to whether the recovered primitive was actually usable for something downstream. Directly negative for Branch Q15 (calibrated score).
6. **The one real-scan test has no ground truth**, so it cannot support any quantitative claim about real-world accuracy, noise level, or type-confusion rate — only two qualitative examples with one visible misclassification (cone→sphere) out of ~90 combined segments. This is far too thin to extrapolate a success/failure boundary for our object set.
7. **Superquadrics / cuboid decomposition are entirely out of scope** for this paper — it is a strict 5-primitive-family (plane, sphere, cylinder, cone, torus) fitting method, so it cannot speak to Branch Q2's question of whether chamfered/rounded real parts force a richer shape vocabulary.
8. **Runtime is per-segment and MATLAB-based**, tens of seconds per segment even for small (400–1,600 point) synthetic clouds; no reported runtime on the large real scans (39–51 segments at hundreds of thousands of points) beyond the aggregate MFE numbers — realistic end-to-end runtime at our object/cloud scale is not derivable from this paper (relevant to Branch Q17's "realistic per-object runtime" question — this paper gives no usable number for that).
9. **No comparison against RANSAC on the same real data with ground truth** — the RANSAC-critique in the intro ("can be easily deceived... in the presence of point cloud artifacts") is a citation to another paper [4], not an experiment run in *this* paper. There is no head-to-head RANSAC-vs-voting number here despite the paper being selected partly for that claim.

## Bottom line for our branch

This is a solid, citable example of the Hough/voting design pattern and a real (if uncalibrated) fit-quality score, but it is a synthetic-noise, infinite-primitive, segmentation-assumed-given paper. It comes closer to Branch Q1/Q7 (axis angular error) and Q6 (partial coverage) than a first read suggested — Fig. 8 does report axis-vector L2 errors and does test ~1/8-coverage partial segments — but only for the pre-refinement initial estimate, under coordinate noise scaled to object radius rather than a sensor model, with no systematic coverage-fraction sweep and no final-fit accuracy number anywhere in the paper. Net effect: it still answers none of the quantitative branch questions in a directly usable way (no number we can put in an error budget, no coverage threshold we can design against, no bounded extents, no sensor-realistic noise, no calibrated failure score) — its value here is as a technique candidate, as a source of concrete negative/qualitative data points (cylinder↔cone confusion under noise; sphere/torus TPR degrading before ACC does; threshold-like rather than graceful axis-error breakdown), and as a caution to verify claims like "no axis error reported" against the actual figures rather than the text search alone.
