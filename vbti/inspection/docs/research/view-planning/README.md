# Geometry-Aware View Planning — Research Workspace

Living knowledge map for the view-planning research. The research framing
(context, problem, goals, RQs, constraints, candidate directions) lives in
[`../geometry-aware-view-planning.md`](../geometry-aware-view-planning.md)
— that doc is the contract; this workspace is the investigation.

## Operating mode

- Anton is the architect. Research runs in **passes**: a wave of threads is
  dispatched, Anton does a readthrough, gives feedback and guidance, the next
  wave is scoped from that. No wave starts without his go.
- Two personas in every artifact: researcher (facts, sources, mechanics) and
  critic (red-team, named hostile expert). Claims survive only after critique.
- Benchmark-driven: no prose-only conclusions about what works.

## Layout

- `knowledge_map.md` — master index, the field as we currently see it
- `flow.md` — journal: decisions, surprises, pivots, dead ends
- `todo.md` — task queue, wave plans
- `results.md` — accepted findings (one entry per closed loop)
- `threads/NN_<topic>/` — research.md / critique.md / open.md per thread
- `hypotheses/` — cross-thread hypothesis cards
- `references/` — captured papers, links, excerpts
- `scratch/` — working notes
