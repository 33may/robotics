# End-to-end Viewpoint Optimization for Inspection based on Defect Detectability Assessment

- Zhang, Fang, Ng (A*STAR Advanced Remanufacturing & Technology Centre, Singapore). AIAT '25 (5th Int'l Conf. on AI and Application Technologies), Kyoto, Dec 4–6 2025; published in ACM DL Feb 2026. DOI: 10.1145/3787120.3787121. Pages 16–21 (6-page short paper). CC BY 4.0 — genuinely open access; ACM's own page just sits behind a Cloudflare bot-check, not a paywall. Full text retrieved via the ACM PDF endpoint (not the abstract-only `/doi/full/` HTML, which strips the equations and only shows the AI summary teaser to non-Premium accounts).
- Selected for this branch because it's the most on-target hit: an image-space viewpoint-quality metric built specifically for defect detectability, plugged into an end-to-end differentiable optimization loop.

## Core method

**Setup (Sec. 3).** CAD model `M = {V, F, T}` (vertices/faces/textures), pre-aligned to origin, upright. Defects `{d_i}, i=1..N_d` are **parameterized ellipsoid-like shapes**, either manually placed or randomly boolean-cut into `M` — i.e. defect location and geometry are **known ground truth at optimization time**, not discovered. Viewpoint `v = [pos, dir]`, `pos=(x,y,z)`; `dir` is constrained to always look at the centroid of the defect cluster, collapsing the search to **3 DOF (camera position only)**. Illumination is a coaxial ring light rigidly aligned with the camera axis (fixed offset) — not optimized in this paper.

**Simulation (Sec. 4.1).** Blender scene as digital twin; Mitsuba 3 (Jakob et al. 2022) as the differentiable ray-tracing renderer, Phong shading for the scene image `I_Scene`, silhouette rendering for a binary defect mask `I_Mask` and an object-silhouette mask `I_objMask`.

**Viewpoint quality metric — four image-space terms, all computed on rendered masks (Sec. 4.2):**

- **Visibility (Eq. 1)**, hard binary gate: `Vis(I_Mask) = 0 if n_d(I_Mask) < N_d, else 1` — 0 unless *every* defect is detected in the mask. Not a soft/smooth term.
- **Size (Eq. 2)**: `Size(I_Mask) = Σ_i Σ_j I_Mask(i,j)/255` — total labeled-white-pixel count across the whole mask (sum over all defects combined, not per-defect then pooled). Prose states "each defect should occupy at least 16 pixels" but this threshold is **not** encoded in Eq. 2 itself — only asserted in text, never enforced.
- **Distance-to-boundary (Eq. 3)**: `DisB = (1/N_d) Σ_i min_dist[C(d_i), B(I_objMask)]` — mean, over defects, of each defect's centroid distance to the object-silhouette boundary `B`. Larger (farther from the edge) is better.
- **Distance-to-center (Eq. 4)**: `DisC = (1/N_d) Σ_i ‖C(d_i) − (w/2, h/2)‖` — mean offset of defect centroids from image center. Smaller is better.
- **Score (Eq. 5)**: `Score = Vis · (α·Size + β·DisB + γ·(1 − DisC))`. Each of Size/DisB/DisC is normalized to [0,1] before combining (procedure for normalization — min-max across the candidate set vs. by image diagonal, etc. — is **not specified**). **α, β, γ values are never disclosed anywhere in the paper.**

**Downstream task (Sec. 4.3).** Pixel-wise defect segmentation via U-Net (encoder-decoder), pretrained on public COCO-annotated real 2D datasets — NEU-DET, GC10-DET, Severstal (all steel/metal-surface defect sets), 512×512, random-flip augmentation. Metric is **GIoU** = `IoU − |C\(A∪B)|/|C|` (Eq., Sec 4.3), where `C` is the convex hull of prediction `A` and ground truth `B`. This pretrained U-Net is folded into the optimization loop as a differentiable-ish detector proxy.

**Initialization (Sec. 4.4, Fig. 4).** 91 candidate viewpoints sampled uniformly over the **upper hemisphere of an icosphere**, radius fixed to the specified camera working distance (standoff is a fixed hyperparameter, not searched). Render all three images per candidate, compute Eq. 1–5, rank by Score, take the argmax as the initial pose for gradient refinement.

**End-to-end optimization (Sec. 4.5, Figs. 5–6).** `Loss = g(I) = λ·L_VA + (1−λ)·L_detect`, with `L_VA = 1 − Score` and `L_detect = 1 − GIoU`. Gradients `∂I/∂P` (P = camera position) flow through the Mitsuba 3 differentiable renderer; `∂Loss/∂P` guides SGD/Adam over `N_loop = 50` iterations. **No λ value, learning rate, or convergence criterion is reported.**

**Real-world validation (Sec. 5).** Basler acA2440-35um camera + F25 lens; coaxial white ring light; **two separate UR robotic arms**, one holding the light, one holding the camera (decoupled illumination/camera rig — unlike our fixed onboard D405 projector+camera). Optimized sim viewpoint mapped to physical robot coordinates; real captured image is claimed to "closely match" the simulated render (Fig. 8a vs 8b) — this claim is **qualitative only, no registration-error number given**. Pretrained U-Net segments defects on the real image (Fig. 8c, 9c). Two demo cases: 1 defect (Fig. 8) and 3 defects (Fig. 9), on a single unnamed "metal component."

**Stated limitations (Sec. 6, authors' own words):**
1. Optimization is run for a **fixed, known** defect set — real-world ROI inspection with unknown defect location is named as unsolved and left to **future work** ("we could randomly generate multiple defect sets within the ROI...").
2. Lighting parameters are not optimized — also future work.
3. Framework claimed "generalizable to other downstream vision tasks" but this is asserted, not tested.

## Concrete results / numbers

There are effectively **none**. No table, no IoU/GIoU values, no pixel counts, no timing, no weight values (α, β, γ, λ), no learning rate, no ablation, no baseline comparison, no cross-object test (N=1 object, 2 defect-count configurations, purely qualitative before/after figures). The abstract's claim that "experiments demonstrate... improving inspection image quality and detection accuracy" is **not backed by any reported metric** — it's shown via side-by-side figures only. Treat this paper as a source of **formula shapes and architecture pattern**, not of citable numbers.

## Load-bearing assumptions

- Complete, watertight, **textured CAD mesh** as the geometric substrate — not a real, noisy, fused survey point cloud. This is the opposite starting condition from ours.
- **Defect location and shape are known ground truth**, injected synthetically. The branch's document-selection note describing this paper as "handles unknown defect location by ROI sampling" is **incorrect / premature** — that is Section 6 future work, not implemented.
- Camera orientation is not free (look-at constraint); standoff/working distance is fixed at the icosphere-sampling stage. Only 3 position DOF are ever searched.
- Illumination geometry (coaxial ring light) is fixed and never varied or optimized.
- Single object, single target view — no multi-view coverage problem (this is a genuinely single-view-scoped paper, a good match to this branch's boundary).
- Validation is qualitative; there is no quantified sim-to-real gap even in the paper's own demonstration.

## What transfers to our setting

- **The two-stage "discrete candidate scoring for initialization → differentiable gradient refinement" pattern (Sec. 4.4 → 4.5) is a clean, working, concrete precedent** for the branch's local-optimization-vs-discrete-action-space question: sample a hemisphere of candidates, score with a cheap closed-form metric, pick the argmax, then locally refine with a differentiable renderer and SGD/Adam for a fixed small number of steps (50). Directly informs whether refinement belongs offline (at action-space construction) vs online: this implementation is **offline / one-shot**, run once per fixed defect configuration, with no reported timing that would support an interactive "VLM asks for better" loop.
- **A working example of a bounded, normalized, [0,1] per-view score reused identically as both a ranking function (Sec 4.4) and a differentiable loss term (`L_VA = 1 − Score`, Sec 4.5)** — direct precedent for the branch's Q8 (bounded normalized per-view score comparable across views). Caveat: "comparable across objects" is asserted by construction (normalize-to-[0,1]) but never tested — only ever run on one object.
- **A genuinely informative negative-shaped data point for the term-inventory table**: this inspection-specific viewpoint-quality metric has **no explicit incidence-angle/cosine term at all**. Orthogonality-like preference appears only *implicitly*, through Size (foreshortening shrinks the defect's rendered pixel footprint as incidence angle grows) and DisB (grazing views push defect projections toward the silhouette boundary). Worth recording in the branch's Q5 table as "incidence/cosine: absent, present only implicitly via Size+DisB" — a real precedent that at least one working inspection-viewpoint-quality system was built without a cosine term.
- **All four terms (Vis, Size, DisB, DisC) are unambiguously image-space**, computed from rendered masks, not PLY-space — useful precision for the branch's PLY-vs-image-space table entry.
- **Aggregation pattern**: hard AND-gate (min-like) for the binary visibility term across defects, but **mean pooling** (not worst-case/min pooling) for the continuous distance terms DisB/DisC. This is a data point against defaulting to worst-point pooling for continuous quality terms — the one working system in this space gates hard on feasibility and averages soft quality.
- **Sim-to-real architecture shape is directly analogous to ours**: Blender/Mitsuba digital twin, optimize a viewpoint in sim, map to real robot (UR arms) coordinates, validate with a real camera capture — reinforces feasibility of a "optimize-in-sim-then-deploy" workflow, though unquantified here.
- Supports the branch's Q19 hypothesis (image space sees things PLY space can't) in a narrow sense: the paper's whole premise is that defect appearance *under specific illumination* can only be judged by rendering/capturing an image, not read off CAD geometry alone — but its scope is limited to Phong-shaded appearance/foreshortening/framing, not exposure, motion blur, or focus.
- **A textbook example of ground-truth circularity** for Branch 2's handoff (Q22): "best view" here is literally defined as `argmax(Score)`, the pipeline is optimized to maximize `Score` (plus `GIoU` from a frozen detector), and "success" is reported by showing the optimized image looks good and the detector fires — no independent, held-out definition of best view exists. Cite this as a concrete, current (2025/26) instance of the metric-based-ground-truth circularity risk the branch's taxonomy already anticipates.

## What does NOT transfer, and why

- **Zero relevance to the D405 incidence-vs-depth-error question (Q1).** This is a 2D machine-vision camera (Basler) + ring light, not a stereo/structured-light depth sensor. No depth error, no RGB-D content anywhere. Source Q1 elsewhere.
- **No angle-penalty shape (smooth vs. knee, Q2) is reported** — there is no incidence-angle term in the metric at all (see above), so there is nothing to characterize as smooth or thresholded with respect to angle specifically. The paper's own `Vis` term *is* a hard 0/1 threshold, but it thresholds on defect-mask detection count, not on incidence angle — useful only as a general precedent that this literature does use hard feasibility gates alongside smooth quality terms, not as an angle-specific answer.
- **No specular/glossy-surface treatment (Q3)** despite using a Phong BRDF (which has a specular lobe) — never discussed, never leveraged for avoiding glare, never tested on glossy materials.
- **No raking/oblique-illumination defect-enhancement treatment (Q4's industrial-inspection answer)** — the ring light is always coaxial with the camera (near-normal incidence), so the classic industrial practice of using grazing/raking light to shadow-reveal shallow dents and scratches is structurally excluded from this system by its own optical design. The paper never raises or tests the "orthogonal ≠ best-lit for shallow defects" tension the branch's Q4 is asking about.
- **The entire method requires a complete, watertight, textured CAD mesh with known defect ground truth** — it cannot run on our defective fused PLY (no mesh, mm pose error, dropout holes, unknown defect locations). For Q10/Q11's partition: bucket this whole term family as **"needs a mesh (and known defect ground truth) we do not have,"** not computable-today.
- **No point-cloud-specific occlusion handling (Q11)** — occlusion/visibility comes for free from ray-traced rendering of a complete mesh (z-buffer/ray tracing), not from hidden-point-removal on a sparse cloud. Not informative for HPR robustness questions.
- **No geometric-uncertainty propagation (Q7, Q12)** — the CAD model is treated as ground truth, zero noise. Reinforces "if nobody does this, it's a contribution claim."
- **No normal-estimation dependency at all (Q7)** — none of the four terms use surface normals; they're all 2D-mask-derived. This paper cannot supply a normal-error sensitivity curve because it has no normal-error-dependent term.
- **No quantitative ablation (Q6, Q24)** — no reported correlation between Size/DisB/DisC/Vis, no sweep of the score vs. detection-loss weight `λ`, no comparison against a naive/geometric-only baseline viewpoint. Cannot be used as an ablation-protocol exemplar; flag as a negative finding for Branch 2's Q24 (an example of a paper that claims effectiveness without demonstrating it numerically).
- **No fused-cloud coordinate-frame issue (Q13)** — not applicable; there is no fusion step in this pipeline.
- **No off-the-shelf VLM anywhere (Q21)** — the judge is entirely hand-crafted (Eq. 1–5) plus a trained CNN segmentation network, not an LLM/VLM.
- **Object set is a single unnamed "metal component"** (Q23, Branch 2 handoff) — not a primitive box/cylinder, not a public/named benchmark object, N=1 with 2 defect-count variants. Do not cite this as evidence the method generalizes across shape classes.
- **The branch's document-selection description overstates the paper**: "also handles unknown defect location by ROI sampling" is **not implemented** — it is proposed only as future work in Section 6. This should be corrected upstream when synthesizing the branch.

## Bottom line

A clean, small, formula-transparent example of an **image-space, illumination-aware, defect-detectability viewpoint score** wired into a discrete-sample-then-differentiable-refine pipeline — useful chiefly as an **architecture and formula-shape precedent** (bounded score, hard visibility gate + smooth quality terms, mean pooling over defects, sample-then-gradient-refine, sim-to-real via digital twin) and as a **clean circularity example** for Branch 2. It supplies essentially no numbers, no ablations, no sensor-depth content, no point-cloud/mesh-uncertainty handling, and — contrary to the branch's selection note — does not yet solve unknown-defect-location inspection. Most of the branch's hard technical questions (D405 depth-vs-angle curve, specular avoidance, raking-light detectability, normal-error sensitivity, fused-PLY robustness) must be answered from other sources; this paper's contribution to those is negative-but-informative (shows what a real, working inspection-viewpoint metric chose to leave out).
