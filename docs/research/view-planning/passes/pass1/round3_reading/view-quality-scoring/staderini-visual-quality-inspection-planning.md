## Core method (Chapter 6 = the IROS 2024 paper)

**Problem it solves:** a set of *N* inspection-pose candidates (IPCs) has
already been generated by ray-casting-based coverage evaluation over a CAD
mesh (from a separate stage, Ch. 3 of the same thesis / the ICPRS 2023
precursor paper). Some fraction of these IPCs — call the index set Υ — are
kinematically **infeasible** (violate joint limits or would self-collide);
the paper's contribution is a way to convert each infeasible IPC into a
feasible one that keeps as much of its original coverage as possible, rather
than discarding it or naively clamping it.

**Kinematic feasibility (§6.2, p.79):** an inspection pose ι_j = h(q_j) is
feasible iff (i) all joint coordinates lie within their limits, q_j[l] ∈
[q̲_l, q̄_l], and (ii) the robot is not in self-collision or environment
collision. Everything else (whether the *pose itself* is good) is decided
upstream, before this chapter, purely by the visibility matrix (below).

**Visibility matrix V (Ch. 2, §2.2, eq. 2.8, p.19)** — this is the paper's
entire formal notion of "view quality," and it is worth stating precisely
because it answers several branch questions directly:

> A surface element s_i (a mesh triangle) is "covered" by viewpoint v_j iff
> **all** of: (i) hit by ≥1 ray from the sensor (line-of-sight, not
> occluded) and within the FOV; (ii) within the sensor's depth of field
> (DOF); (iii) the incidence angle θ between the ray and the surface normal
> is **below a threshold specific to the sensor and the material**; (iv) for
> a projector+camera structured-light rig, conditions (i)–(iii) hold
> **simultaneously for the projector ray and at least one camera ray**.
> V_ij ∈ {0,1} — binary, no continuous weighting.

Two aggregate quantities are built from V and used everywhere downstream:
- **Coverage** Cov = (1/NM) Σ_j Σ_i V_ij (eq. 2.9) — dataset-level mean
  fraction of (element, view) pairs that are visible.
- **Per-view coverage** Cov(ι_j) = (1/M) Σ_i M_ij (eq. 6.11, used as
  optimization objective F2) — the per-view score is a **plain arithmetic
  mean over mesh faces of the binary visibility flag**. No area weighting,
  no worst-point/min pooling, no continuous quality gradient — it is exactly
  "fraction of mesh triangles this pose can see," bounded in [0,1] and
  comparable across views and objects by construction (it is always a
  fraction of that object's own face count).
- **Viewability** ν(s_i) = (1/N) Σ_j V_ij (eq. 2.10) — the complementary
  per-*element* score: how many of the N candidate views can see this
  element at all. Used to flag hard-to-see elements, not for view ranking.

**Refinement objective (§6.2, eqs. 6.7–6.17, pp.80–84).** For each infeasible
q_j (j ∈ Υ), an initial feasible seed q̃_j is obtained by **orthogonal
projection onto the joint-limit box** (eq. 6.4–6.6, closed-form
componentwise clamp — this is literally the "Box Constraints" (BC) baseline
they later benchmark against, used here only as an initialization). Then a
derivative-free optimization is run over q'_j ∈ [q̲, q̄] with a
three-term objective:
- **F1** — preserve the *original* coverage set: let Γ_j = indices of faces
  *not* seen by the original infeasible q_j; project out those rows and
  require the remaining ("originally visible") faces to still read 1
  (eq. 6.10, `π_Γj[c(q'_j)] − 1`‖²). A naive "match the whole coverage
  vector" objective (eq. 6.8) is explicitly tried and **rejected as
  ineffective** because it also penalizes newly-gained coverage of
  previously-unseen faces — a clean negative result on the "just minimize
  vector distance" approach.
- **F2** — maximize the refined pose's own coverage, Cov(q'_j) (eq. 6.12).
- **F3** — maximize coverage of faces *not yet covered by any already-fixed
  feasible pose* (uses a running matrix M̄ over Φ, eq. 6.13–6.16) — this is
  the term that prevents all refined poses collapsing onto the same
  easy region of the object.
- Combined: F(q'_j) = a·F3 + b·F2 + 1/F1, solved by **Bayesian optimization**
  (expected-improvement acquisition, open-source `BayesianOptimization`
  Python package [110], domain reduction, **60 iterations per pose**,
  CPU-only, no GPU) — chosen specifically because F1–F3 are built from
  discrete ray-casting hit/miss visibility, i.e. **non-differentiable /
  discontinuous in pose**, ruling out gradient-based refinement for this
  objective (§6.2, p.84; the reasoning is implicit in the objective's
  construction, not stated as a rejected alternative, but no gradient
  method is used or discussed anywhere in the chapter).

**Camera-fixed vs object-fixed equivalence (§6.2, eqs. 6.1–6.3, p.79):**
candidates v_j are generated assuming a *moving camera, fixed object*
(matches our eye-in-hand UR5e+D405 setup exactly — this is "System 1" in
their Ch.2 taxonomy, n_2 = 0). Their own lab rig is the *opposite*
configuration (fixed sensor, 3-DOF stage moves the object), so they convert
via H^O_Cj = H^C_Oj (the relative camera↔object transform is preserved
regardless of which physical system moves) — a reusable pose-space identity,
not evidence that their specific mechanism transfers to an eye-in-hand arm.

## Concrete results (Table 6.1, p.87 — the paper's headline numbers)

Compared: **BC** (Box Constraints — orthogonal-projection clamp only, no
optimization) vs **WS** (Workspace Sampling — uniform IK-feasible sampling,
geometry-agnostic) vs **BO** (their method). Same visibility/sensor model,
same object set, same #IPC per object — a clean single-protocol ablation.

| Object | Method | #IPC | #OFIP (poses used) | Coverage (%) |
|---|---|---|---|---|
| Parallelepiped | BC / WS / BO | 50 | 10 / 8 / 6 | 98.70 / 99.77 / **100.00** |
| Rabbit | BC / WS / BO | 50 | 19 / 17 / 20 | 60.75 / 95.02 / **99.52** |
| Bracket | BC / WS / BO | 100 | 36 / 29 / 28 | 55.92 / 97.55 / **99.60** |
| Gear | BC / WS / BO | 50 | 18 / 20 / 21 | 68.11 / 97.11 / **99.80** |
| Hirth coupling | BC / WS / BO | 50 | 9 / 8 / 7 | 72.82 / 98.55 / **99.77** |

(Averaged over 5 runs.) Simulated sensor: modeled on the **Zivid One+ S1**
structured-light sensor (camera 1920×1200 px, 38.70°×24.75° FOV; projector
1140×912 micromirrors, 45.23°×24.75° FOV, 15° tilt, 137 mm baseline; DOF
350–700 mm). WS needed **1000** candidates (vs BO's 50–100) to reach only
98.6%/98.4% coverage on gear/Hirth — the paper's efficiency claim ("fewer
optimal viewpoints") is about candidate-count-to-coverage ratio, not raw
optimization speed. Real-world validation: same 3-DOF rig (PI linear axis +
PI rotary table + PI goniometer, object moves in front of fixed Zivid
sensor), objects = 3D-printed rabbit/parallelepiped/gear/Hirth plus an
industrial bracket in **both plastic and aluminum alloy** (Fig. 6.4) —
reported qualitatively as "fully covered," **no material-stratified
coverage numbers are given** in this chapter (Table 6.1 explicitly says it
was computed "neglecting any information about the material" — material
photometrics are a separate chapter/paper, see below).

Table 6.1 is exactly the "ablation that earns a term its place" pattern the
benchmarking branch wants verbatim: it isolates the refinement strategy
while holding candidate generation, visibility model, and object set fixed.

## Load-bearing assumptions (what makes the method work)

1. **A CAD mesh is known a priori.** Ch.2 §2.2, p.17: "we adopt a
   model-based approach... where both the target object model and the sensor
   specifications are known a priori... leveraging CAD models... converted
   into discrete mesh representations." All coverage/visibility is computed
   by ray-casting against this ground-truth mesh with known object pose —
   never against a reconstructed/fused point cloud. There is no mesh-quality,
   registration-error, or reconstruction-uncertainty term anywhere in the two
   chapters read.
2. **Sensor is an active structured-light rig with a projector**, not a
   passive/active-IR stereo camera like the D405 — condition (iv) requires
   *both* camera and projector rays to independently clear the incidence
   threshold. No depth-error-vs-range-and-angle curve is given anywhere;
   incidence angle is used purely as a **binary admissibility gate**.
3. **Kinematics is 3-DOF** in both simulation and real experiments (linear +
   rotary + goniometer moving the object; fixed sensor) — not a 6-DOF
   eye-in-hand arm. (The thesis's later Ch. 7 claims validation up to 8-DOF,
   but that is a different chapter/paper, not this document.)
4. **Fully offline, CPU-only planning.** Explicitly stated as a non-issue:
   "increasing the number of Bayesian iterations extends computation time,
   [but] this is inconsequential for industrial applications with offline
   inspection planning" (p.88). No online/interactive latency budget is
   assumed anywhere — refinement happens once, at plan-construction time,
   never in response to an online request for "a better view."
5. **Coverage, not per-view "quality," is optimized.** There is no notion in
   this chapter of "how good is this one image" beyond the fraction of mesh
   faces it can geometrically see under threshold conditions. Framing,
   standoff/GSD, defect detectability, and image-space quality are entirely
   out of scope for Ch. 2/Ch. 6.

## What transfers to our setting

- **The visibility-matrix formalism is the field's de facto standard
  per-point/per-view quality primitive** (binary, occlusion ∧ FOV ∧ DOF ∧
  incidence-threshold), traceable through their own citation chain to Scott
  & Tarbox/Gottschlich 1995 ("Planning for complete sensor coverage in
  inspection," ref [27]) and W.R. Scott 2009 "Model-based view planning"
  (ref [31]) — i.e., this is the **Scott/Tarbox lineage**, not the
  Tarabanis/Cowan "Generalized Viewpoint" constraint-satisfaction lineage
  (searched the full 151-page thesis text for "Tarabanis" / "Cowan" /
  "generalized viewpoint" — **zero hits**; this modern industrial-inspection
  branch of the literature does not cite or build on the classical GVP
  formulation at all — a genuine negative finding for the branch's synthesis
  question comparing the two traditions).
- **Incidence angle is answered as a hard threshold, not a smooth
  weight**, directly and repeatedly, across every chapter of this framework
  that touches it (Ch.2 def., Ch.6 use, and Ch.4's concrete number: **75°
  maximum permissible incidence angle**, θ̄_c/θ̄_p, used consistently as a
  binary cutoff in simulation — cited here as corroborating evidence from
  the same visibility formalism, not from the IROS 2024 chapter itself,
  since that specific number lives in Ch.4/the ICVS 2023 paper). This is a
  direct, citable answer to the branch's "smooth vs threshold" question for
  this line of work: **threshold, with ~75° as the field's working cutoff**,
  used purely as a feasibility gate, not folded into any weighted score.
- **A bounded, comparable per-view score already exists and is exactly
  Cov(ι_j) ∈ [0,1]** — mean fraction of that object's mesh faces visible
  under the threshold conditions. It is comparable across views (same
  denominator convention) and across objects (both normalized by each
  object's own face count) — a legitimate existence proof for the branch's
  "is there precedent for a bounded, normalized per-view score" question,
  though it measures *quantity* of surface seen, not *quality* of the
  viewing geometry per face (no incidence-weighted variant reported).
  Per-face aggregation is **strict mean pooling** — no worst-point/min
  pooling appears anywhere; this is a negative data point against
  worst-point pooling being the field's default.
- **Refinement is offline, single-shot, per-candidate-at-construction-time**
  — directly answers the branch's "does local optimization belong offline
  or online" question for this paper: unambiguously offline, matching our
  project's own likely answer (refine the discrete action-space candidates
  once when building the space, not per VLM request).
- **Sampling (Bayesian optimization) is chosen over gradient methods
  specifically because the visibility-derived objective is discontinuous**
  in camera/joint pose (ray-casting hit/miss) — corroborates the branch's
  own concern that "visibility is discontinuous in camera pose" and is a
  real instance of a team hitting that wall and picking derivative-free
  search rather than smoothing the objective.
- **The naive "minimize distance to original coverage vector" objective is
  explicitly tried and rejected** (eq. 6.8, p.81–82) in favor of the
  set-membership formulation (F1) — a small but genuine negative result
  worth keeping: matching a binary visibility vector by L2 distance actively
  fights against gaining new coverage.
- The camera-fixed/object-fixed pose-equivalence identity (eqs. 6.1–6.3) is
  a clean, reusable piece of notation for converting between "camera moves"
  and "object moves" viewpoint conventions, applicable regardless of which
  system is our eye-in-hand rig.

## What does NOT transfer / negative findings

- **No answer to the D405/incidence-angle-vs-depth-error question.** This
  paper (and its two sibling chapters) never reports a σ(range, θ) curve or
  any functional depth-noise model — incidence angle is consumed only as a
  yes/no gate. For that specific branch question, this document is a dead
  end; a photogrammetry/RGB-D-metrology-specific source is still needed.
- **No handling of a defective fused survey cloud.** The entire pipeline
  requires a known CAD mesh and known object pose; there is no discussion of
  point-cloud fusion error, registration offsets, dropout holes, or
  propagating input-geometry uncertainty into the visibility/coverage score.
  This is a genuine gap in the literature this document represents — it
  supports treating "score views against a cloud that is itself wrong" as an
  open contribution opportunity rather than assuming someone has solved it.
- **No specular/glossy-surface treatment in this chapter.** Materials appear
  only as a robustness demonstration (plastic vs. aluminum bracket scanned
  successfully), with **no photometric or BRDF modeling and no
  material-stratified numbers** — Table 6.1 is explicitly material-blind.
  The same author group *does* build a photometric visibility matrix with
  Blinn-Phong/Cook-Torrance BRDFs that excludes saturated/underexposed
  regions, but that is thesis Chapter 5, attributed to a **different**
  paper — V. Staderini et al., "Photometric visibility matrix for the
  automatic selection of optimal viewpoints," 3DV 2024 (thesis ref [17],
  not accessed/read as part of this task; flagged here only as a pointer for
  a future targeted read if the "does orthogonality ever hurt" question
  needs a direct source).
- **No image-space judging, no defect-detectability-vs-angle treatment, no
  learned/VLM component anywhere.** The method is pure classical
  geometric/kinematic optimization over a known mesh; it has nothing to say
  about captured-image quality, exposure, motion blur, or actual defect
  contrast.
- **Kinematics is 3-DOF, not a 6-DOF eye-in-hand arm**, and evaluation
  objects are mostly free-form/mechanical parts (rabbit, gear, Hirth
  coupling, bracket) at 2–40 cm scale, not primitive box/cylinder shapes —
  only the "parallelepiped" object (27–40 cm) is a clean primitive analog to
  our setting. This weakens direct transfer of the *specific* numbers in
  Table 6.1 to a primitive-shape regime, though the method itself is
  shape-agnostic (it only consumes a mesh + visibility matrix).
- **No presented per-view judge that a VLM or other agent could call
  online** — refinement is a one-time offline optimization pass baked into
  action-space construction, so it does not by itself answer RQ4
  (presenting/navigating the space); it only answers "how was this
  candidate action space built and pruned," which is upstream of RQ4.
