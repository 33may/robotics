## Core idea

The paper is a **coverage path planner for free-flying aerial vehicles inspecting a known triangular mesh**, not a view-*selection* method. Its central design decision, stated explicitly twice (Sect. I and II), is to **not** treat view-set minimization as a goal at all:

> "As the algorithm does not focus on minimizing the number of viewpoints, the proposed approach selects one (admissible) viewpoint for every triangle in the mesh of the structure to be inspected." (Sect. IV, opening)

> "The proposed fast inspection path planner retains a two-step optimization structure but contrary to trying to find a minimal set of guards in the AGP it rather tries to sample them such that the connecting path is short while ensuring full coverage. This is driven by the idea that with a continuously sensing sensor the number of viewpoints (and if this is minimal or not) is not necessarily important but mostly their configuration in space." (Sect. II, closing)

So the "selection problem" this branch cares about (which subset of candidate views to keep) simply does not exist in this paper — coverage granularity is fixed **1:1 with mesh facet count**, decided upstream by whatever tool produced/coarsened the mesh (the GitHub wiki recommends ACVD remeshing to control this, external to the algorithm). What the paper actually optimizes is **Algorithm 1**, a two-step alternating loop:

1. **Initial pass**: sample one arbitrary admissible viewpoint per triangle (coverage-only, unoptimized), compute the full pairwise connection-cost matrix, solve the initial tour with the Lin-Kernighan-Helsgaun (LKH) TSP heuristic.
2. **Iterate** (`while running`): **resample** every viewpoint's position (Sect. IV-B) by solving a per-facet Quadratic Program that minimizes squared distance to its current tour-neighbors (pulling viewpoints together to shorten the tour) subject to hard linear constraints that *define* the admissible/visible region for that facet (incidence angle, min/max range, camera FoV) — then recompute the cost matrix and re-solve the TSP tour with LKH, keeping the best tour found so far.

**This is the paper's precedent value for the branch**: the viewpoint-resampling QP (Eq. 3–4) has the *admissible region itself* as its feasible set — the objective (tour-cost reduction) is optimized only inside constraints that are, by construction, exactly the visibility/incidence/range/FoV region (Eq. 1–2, Fig. 2). A viewpoint can never be pushed outside admissibility; it only slides around inside it, iteration after iteration, chasing a cheaper tour. There is no separate "propose ideal pose → check feasibility → reject/fallback" pipeline — feasibility is baked into the search space from the start. This is a clean, citable instance of "slide inside the admissible region and re-optimize" (branch Q8's fallback-ladder item ii), though note it's *not* quite item (iii) ("optimize in joint space, never leave the feasible set") because there is no joint space here at all — it's a free-flying 6DoF point in Cartesian space with no kinematic chain.

## Concrete results and numbers

**Constraint formulation (Sect. IV-B, Eq. 1–2, Fig. 2):**
- Admissible position `g = [x,y,z]` for a triangle with corners `x_i` (i=1,2,3), normal `a_N`: three half-space incidence-angle constraints `(g − x_i)ᵀ n_i ≥ 0` (one per edge, `n_i` = normal of the separating hyperplane, Fig. 2a) plus two range half-spaces `(g−x_1)ᵀa_N ≥ d_min`, `−(g−x_1)ᵀa_N ≥ −d_max`.
- The vertical FoV cone is non-convex (a revolved 2D cone); it is **convexified by slicing into `N_C` equal angular pieces** (Fig. 2b) and solving each slice's QP independently, keeping the global best. Horizontal FoV constraints are handled by two more half-spaces (`n_right`, `n_left`) referencing the triangle's relevant corners and midpoint; horizontal slack is deliberately left in the position-sampling step and resolved later in the heading-sampling step.
- Heading is solved **after** position, as a separate scalar minimization (`min (ψ_p−ψ_k)²/d_p + (ψ_s−ψ_k)²/d_s` s.t. `Visible(g_k, ψ_k)` = whole triangle visible) — explicit or grid-search depending on sensor simplicity.

**Objective (rotorcraft, Eq. 3–4):** minimize `‖g_k − g_prev‖² + ‖g_k − g_next‖² + ‖g_k − g_k−1‖²` (pull toward tour neighbors, damped by distance to the viewpoint's own previous position) subject to the constraint set above, expressed as a QP with linear constraints, solved with qpOASES [6].

**Fixed-wing extension (Sect. IV-C, Eq. 5–9):** adds a straight-line-alignment term (minimize squared perpendicular distance to the line between tour neighbors, Eq. 5–6) to reduce path curliness under Dubins-curve dynamics (min turn radius `r_min`), plus linearized (conservative) minimum-separation constraints with two slack variables `p,s` (penalized by constant `C`) to allow occasional violation rather than infeasibility — the only place in the paper where a soft/relaxable constraint appears, and it's a *spacing* constraint for path smoothness, not a view-quality constraint.

**Heuristics (Sect. IV-D):** two convergence accelerators, both schedule-based, not selection-related — (1) early iterations connect each viewpoint to neighbors `N_neighbour` steps away on the tour rather than nearest, decaying `N_neighbour → 1`; (2) allowable yaw rate is ramped up from a lower initial value to `ψ̇_max`.

**Complexity (Sect. V):** LKH TSP solve dominates for large N at `O(N^2.2)` [Helsgaun's own bound]; viewpoint (re)sampling is `O(N)` (constant-cost QP per facet); pairwise distance/cost-matrix computation is `O(N²)`. For fixed-wing, the asymmetric TSP (doubling viewpoints for direction of travel) and BVS calls quadruple, making distance computation the dominant cost share instead of LKH (Fig. 5a).

**Scalable synthetic benchmark (Table I, Figs. 3–6):** triangular-tiled plane, height 1250 m, width 2165 m (area 2.71 km²), `N_facets` swept 100→3600, incidence angle 30°, FoV [70°,70°] (60° usable horizontal after margin), mounting pitch 25°, unconstrained range, height 200 m, rotorcraft `v_max`=5 m/s, `ψ̇_max`=0.5 rad/s, fixed-wing `v_FW`=9 m/s, `r_min`=60 m. Iterations: 25 for N<900, 50 for N≥900 (rotorcraft); 25 up to N=900 (fixed-wing). Hardware: single-thread C++, 1.73 GHz, Ubuntu 14.04. Comparison to a naive sweeping path (image baseline ≈190 m, 7 sweeps × 2165 m + 6× baseline translation, 5 m/s): sweeping cost = 3259 s vs. the proposed algorithm's cost at 100 facets = **1234.90 s** — "more than double" — but the paper is explicit this is a weak-form comparison, the real payoff is claimed for complex 3D geometry where sweeping doesn't apply at all.

**Beijing TV Tower simulation (Table II, Fig. 7):** 405 m structure, mesh `N_facets`=1701, incidence 30°, FoV [120°,120°], mounting pitch 15°, `d_min`=10 m, `d_max`=25 m, rotorcraft `v_max`=2 m/s, `ψ̇_max`=0.5 rad/s. Result: **92 s** computation time, path cost **2997.44 s**.

**Rotorcraft trolley experiment (Table III, Figs. 8–9):** real hexacopter (AscTec Firefly + VI-Sensor), mesh from terrestrial-image SfM reconstruction, `N_facets`=106, incidence 30°, bounding box 3×3×2.75 m, FoV [60°,90°], mounting pitch 15°, `d_min`=1 m, `d_max`=3 m, `v_max`=0.25 m/s, `ψ̇_max`=0.5 rad/s. Result: path cost **151.44 s**, flown and reconstructed with Pix4D, reported as "excellent" 3D reconstruction quality.

**Fixed-wing Marche-en-Famenne field trials (Table IV, Figs. 10–12):** 5.6 m wingspan AtlantikSolar UAV, two missions each on an **8-facet** (`N_facets`=8) GIS-derived coarse mesh, incidence 30°, `v_FW`=9 m/s, `r_min`=60 m, FoV [90°,50°] and [120°,120°] for the two camera configs, mounting pitch 50°/90°, unconstrained range, reference altitude 362 m / 342 m (120 m / 100 m above highest point). Both missions flown and reconstructed; the paper notes explicitly that the resulting point clouds are "very dense," attributing this to short-path high-overlap coverage being *useful* for SfM reconstruction, not a defect.

## Load-bearing assumptions (and where they break for us)

1. **Free-flying 6-DoF platform, no kinematic chain.** Both vehicle models (rotorcraft: position+yaw with near-zero roll/pitch; fixed-wing: Dubins xy-plane + constant climb/sink rate) treat the vehicle as a point with simple dynamic limits. There is no joint space, no IK, no self-collision, no fixed base, no reachable shell. This is the single largest assumption gap relative to our tabletop UR5e+RG2+D405 setting — **nothing here transfers to RQ9–RQ12** (IK multiplicity, capability maps, reachable-shell coverage loss). Obstacle avoidance is handled only as a path-segment fallback (RRT* if the direct BVS connection is blocked, obstacles approximated as cuboids), never as a per-viewpoint reachability filter.
2. **Known, clean mesh, produced upstream.** The structure's mesh comes from CAD, GIS data, or offline SfM reconstruction (e.g., the trolley mesh from terrestrial images, the Beijing Tower mesh from a public 3D-warehouse model). The paper never touches a "defective" survey cloud with pose error, dropout, or a fused-vs-single-view offset — geometry quality is a non-issue by assumption. Directly answers one branch question in the negative: **this is not precedent for planning views from a defective self-acquired survey cloud** (that gap remains open).
3. **View density is set externally by mesh resolution, not derived from any per-primitive formula.** The "how many views does a primitive deserve" question (branch Q6/Q7) is answered here only by "however many facets the (externally coarsened) mesh has" — there is no FoV/incidence/overlap/defect-size closed form inside the algorithm itself. The GitHub wiki's ACVD-resampling recommendation confirms this is treated as a *preprocessing* decision, not something the planner reasons about.
4. **Orthogonality is a uniform threshold, not a per-region optimized objective.** The minimum incidence angle is fixed at **30° in all four evaluated scenarios** (scalable benchmark, Beijing Tower, trolley, Marche-en-Famenne) — a genuinely reusable, consistently-applied number, but it functions purely as a *feasibility floor* baked into the QP's constraint set (Eq. 1), never as something the objective tries to minimize toward zero (true orthogonality). The tour-cost objective (Eq. 3) has zero orthogonality term. So this paper is weak precedent for "pick the most orthogonal admissible view" (our framing doc's core requirement) — it only guarantees "admissibly non-grazing," not "best."
5. **Continuously-sensing camera, coverage-as-video, not discrete evidence images.** The camera senses continuously along the flown path; "coverage" means every mesh facet is admissibly visible from *some* point on the trajectory, and dense overlapping viewpoints are explicitly desired for downstream SfM reconstruction. This is the mechanism behind the paper's stated redundancy: **1 viewpoint per mesh triangle is not a bug, it is the design goal**, because for a video/photogrammetry pipeline more overlap is strictly better. This is the opposite optimization target from ours (a VLM choosing a small number of discrete, individually-evaluated, non-redundant evidence images) — **directly disqualifying under our small-discrete-set requirement (branch Q13)**, but it is important to represent faithfully: the paper does not present this as a failure it stumbled into, it presents it as a deliberate, justified design choice for a different objective (path-cost-minimizing continuous coverage, not discrete evidence selection). Framing it as "documented to emit redundant views" (as the selection rationale for this reading task does) is accurate as a *consequence for our purposes*, not as a self-diagnosed flaw in the source paper.
6. **No selection/enumeration step exists to be presented to an agent.** The output is a single continuous flight tour, not a discrete, addressable action space — **no transfer to RQ4's "candidates then select, enumerated for a VLM" framing**; there is nothing to enumerate here, the tour is the artifact.

## What transfers to our setting

- **The admissible-region-as-feasible-set construction (Eq. 1–2, Fig. 2).** Defining a per-facet/per-region admissible viewpoint volume via intersected half-spaces (incidence-angle planes off each triangle edge, min/max range planes, FoV-cone-sliced-into-convex-pieces) is a clean, reusable geometric recipe, structurally similar to Magaña et al.'s C-space intersection approach (same directory) but expressed as simple linear/QP constraints instead of closed-form manifold CSG — a lighter-weight version of the same idea, worth citing alongside Magaña as precedent for RQ4's "derive views from constraint intersections" track.
- **The "optimize inside the admissible region, never leave it" mechanism (Eq. 3–4)** is a genuine, checkable precedent for branch Q8's fallback-ladder item (ii) ("slide the viewpoint inside its admissible region and re-optimize") — this is the paper's headline relevance per the selection rationale, and it holds up: the QP's constraint set *is* the admissible region, so resampling is provably feasibility-preserving by construction, not by post-hoc rejection.
- **The convexification-by-angular-slicing trick for non-convex FoV cones (Fig. 2b)** is a directly reusable technique if we ever need to turn a camera-frustum admissibility region into something a convex solver (or simple geometric reasoning) can handle per primitive.
- **Complexity numbers support RQ3's expected answer.** Viewpoint sampling is `O(1)` per facet (cheap QP); the only expensive part (LKH TSP at `O(N^2.2)`) only matters once N reaches the hundreds-to-thousands (92 s at N=1701). At our instance size (tens of candidate views, a handful of primitives), even a brute-force or ILP-based exact selection is trivially cheap by comparison — this paper's own scaling data is indirect but useful supporting evidence that "the field's heuristic apparatus is irrelevant to us at our size" (Q3) is a defensible claim, not just an assertion.

## What does NOT transfer, and why (negative findings — first class)

1. **No answer to Q1 (min-set-cover vs. max-k-coverage vs. per-region quality-under-a-floor).** The paper structurally avoids this question by fixing view count = facet count; it explicitly rejects the "minimal set of guards" (AGP) framing that Q1 is asking us to adjudicate. It cannot be cited either for or against submodularity/minimality arguments — it opted out of the selection problem entirely.
2. **No answer to Q5 ("one orthogonal view per face, a ring per cylinder" precedent).** The unit of work here is a mesh triangle, arbitrarily fine or coarse depending on upstream remeshing — not a semantic primitive face or cylindrical surface. There is no facet-clustering-by-normal-similarity step in this paper (contrast with feature-clustering/normal-deviation-grouping approaches cited elsewhere in this branch); each triangle gets independently sampled. Not usable as a citation link in the "one view per face, ring per cylinder" chain.
3. **No closed-form view-count formula (Q6).** Confirmed above — externalized to mesh coarsening, not derived from FoV/incidence/overlap/defect-size within the algorithm.
4. **Orthogonality threshold present but not optimized (Q7).** 30° incidence-angle floor is a real, consistently-used number worth logging as a data point (a UAV-inspection precedent for "how far off-normal is still acceptable"), but it is a feasibility gate, not a "converts coverage into coverage-at-quality" mechanism the way Q7 is asking for — the paper never varies or ties this number to defect size or resolution requirements; it is applied uniformly and never revisited per scenario reasoning (just re-declared as 30° each time).
5. **Reachability treatment is essentially absent (Q9–Q12).** Free-flying vehicle assumption means there is no capability map, no IK, no false-positive concept, no joint-configuration-vs-Cartesian-pose distinction, and no reachable-shell coverage-loss analysis. Zero transfer value for the ObjView-Bench-style reachability questions this branch is building toward.
6. **Redundancy is disqualifying for us but was a deliberate virtue for them (Q13).** As detailed above — this paper is useful as the *documented instance* of the redundancy failure mode the branch flags, but should be cited carefully: the redundancy is the intended outcome of a different (continuous-coverage, photogrammetric-overlap) objective, not evidence that the resampling *mechanism itself* inherently causes redundancy. If we adopt the resampling mechanism (Q8's transfer) but change the objective to include a discrete-set-size penalty or hard cardinality cap, the redundancy outcome would presumably not follow — worth stating explicitly rather than treating "iterative resampling → redundant views" as a fixed causal law.
7. **No stopping/minimality criterion to compare against SCVP/PRVNet/Chvátal (Q14).** The `while running` loop in Algorithm 1 has no coverage-based termination logic at all — it runs for a fixed iteration budget (25 or 50, set externally per experiment) and returns the best tour found. No auto-stop regime exists here.
8. **No learned component (Q16).** Purely a QP + TSP-heuristic pipeline, no relevance to the learned-vs-analytical selection verdict question, other than as a (very fast, small-instance) analytical baseline data point.
9. **No defective-survey-cloud handling, no primitive decomposition (Q17, Q18).** Both absent by construction (mesh assumed clean and given); this paper is silent on, not evidence against, either gap claim.
